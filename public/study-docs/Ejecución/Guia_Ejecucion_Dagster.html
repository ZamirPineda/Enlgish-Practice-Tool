Guia_Ejecucion_Dagster

Explicación

Esta guía proporciona una configuración básica de Dagster usando Docker Compose (compatible con Podman Compose). Dagster es una plataforma de orquestación de datos que permite definir, desarrollar y monitorear pipelines de datos. Esta configuración incluye:

1. PostgreSQL: Una base de datos para almacenar los metadatos de Dagster (historial de ejecuciones, logs de eventos, etc.). Esto asegura la persistencia de los datos del sistema de Dagster.

2. user_code_server: Un contenedor que ejecuta su código Dagster (activos, trabajos, etc.) como un servidor gRPC. Este contenedor se construye a partir de un Dockerfile personalizado y contiene un ejemplo simple de un activo Dagster.

3. Dagit: La interfaz de usuario web de Dagster, que se conecta al servidor de código de usuario para cargar las definiciones de sus activos y trabajos, y a PostgreSQL para acceder a los metadatos de las ejecuciones.

Pasos para levantar la instancia:

1. Guarde los archivos: Cree la estructura de directorios y guarde los contenidos proporcionados en sus respectivos archivos. Asegúrese de que el directorio my_dagster_project contenga __init__.py, repo.py y requirements.txt.

    .
    ├── docker-compose.yml
    ├── Dockerfile
    ├── dagster_home
    │   ├── dagster.yaml
    │   └── workspace.yaml
    └── my_dagster_project
        ├── __init__.py
        ├── repo.py
        └── requirements.txt

2. Ejecute Docker Compose: Navegue hasta el directorio donde guardó docker-compose.yml y ejecute el comando:

    docker-compose up -d

(O podman-compose up -d si usa Podman Compose).

3. Acceda a Dagit: Una vez que todos los contenedores estén en funcionamiento, abra su navegador y navegue a http://localhost:3000. Debería ver la interfaz de usuario de Dagit con el activo my_first_asset cargado en la sección 'Assets'.

4. Limpieza: Para detener y eliminar los contenedores y volúmenes, ejecute:

    docker-compose down -v

(O podman-compose down -v). El flag -v eliminará también el volumen de PostgreSQL, borrando los metadatos de Dagster.

Archivos de Configuración

Dockerfile

# Dockerfile para el servidor de código de usuario de Dagster
FROM python:3.9-slim-buster

# Establecer variables de entorno
ENV DAGSTER_HOME=/opt/dagster/dagster_home
ENV PYTHONUNBUFFERED=1 # Salida sin búfer para Python

# Crear un directorio de trabajo
WORKDIR /usr/app

# Copiar el archivo de requisitos e instalar dependencias
COPY my_dagster_project/requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Copiar el código del proyecto Dagster como un paquete
COPY my_dagster_project my_dagster_project

# Exponer el puerto gRPC para que Dagit se conecte
EXPOSE 4000

# Comando para ejecutar el servidor de código de usuario de Dagster
# Esto servirá el repositorio definido en `my_dagster_project/repo.py`
CMD ["dagster", "api", "grpc", "--host", "0.0.0.0", "--port", "4000", "--module", "my_dagster_project.repo"]

docker-compose.yml

version: '3.8'

services:
  # Base de datos PostgreSQL para metadatos de Dagster (historial de ejecuciones, logs de eventos)
  postgres:
    image: postgres:13
    container_name: dagster_postgres
    environment:
      POSTGRES_DB: dagster_db
      POSTGRES_USER: dagster_user
      POSTGRES_PASSWORD: dagster_password
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U dagster_user -d dagster_db"]
      interval: 5s
      timeout: 5s
      retries: 5

  # Despliegue de código de usuario de Dagster, ejecutando nuestro `my_dagster_project`
  user_code_server:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: dagster_user_code_server
    # Asegurarse de que este servicio usa la misma configuración de instancia de Dagster
    environment:
      DAGSTER_HOME: /opt/dagster/dagster_home
    volumes:
      # Montar dagster_home para obtener dagster.yaml
      - ./dagster_home:/opt/dagster/dagster_home
    ports:
      - "4000:4000" # Exponer para posible depuración, aunque Dagit se conecta internamente
    depends_on:
      postgres:
        condition: service_healthy # Esperar a que postgres esté listo
    # El comando se define en el Dockerfile

  # Servidor web Dagit (UI)
  dagit:
    image: dagster/dagster-webserver:1.7.0 # Versión de Dagster compatible con las dependencias
    container_name: dagster_dagit
    ports:
      - "3000:3000" # Exponer la UI de Dagit
    environment:
      DAGSTER_HOME: /opt/dagster/dagster_home
    volumes:
      # Montar dagster_home para obtener workspace.yaml y dagster.yaml
      - ./dagster_home:/opt/dagster/dagster_home
    depends_on:
      postgres:
        condition: service_healthy
      user_code_server:
        condition: service_started # Dagit necesita que el servidor de código de usuario esté activo para cargar definiciones
    command:
      [
        "dagster-webserver",
        "-h", "0.0.0.0",
        "-p", "3000",
        "-D", "/opt/dagster/dagster_home", # Directorio para la configuración de la instancia de Dagster (dagster.yaml)
        "-w", "/opt/dagster/dagster_home/workspace.yaml" # Archivo workspace apuntando al código de usuario
      ]

volumes:
  postgres_data:

dagster_home/dagster.yaml

# dagster_home/dagster.yaml: Configuración para la instancia de Dagster.
# Este archivo le indica a Dagster cómo conectarse a su base de datos de metadatos.
run_storage:
  module: dagster_postgres.run_storage
  class: PostgresRunStorage
  config:
    postgres_db_name: dagster_db
    postgres_host: postgres
    postgres_port: 5432
    postgres_user: dagster_user
    postgres_password: dagster_password
event_log_storage:
  module: dagster_postgres.event_log
  class: PostgresEventLogStorage
  config:
    postgres_db_name: dagster_db
    postgres_host: postgres
    postgres_port: 5432
    postgres_user: dagster_user
    postgres_password: dagster_password

dagster_home/workspace.yaml

# workspace.yaml: Define dónde Dagit puede encontrar los repositorios de Dagster.
load_from:
  - grpc_server:
      host: user_code_server # Esto coincide con el nombre del servicio en docker-compose.yml
      port: 4000
      location_name: my_dagster_project_repo # Un nombre lógico para la ubicación del repositorio

my_dagster_project/repo.py

# my_dagster_project/repo.py: Contiene un activo simple de Dagster y una definición de repositorio.
from dagster import asset, Definitions

# Definir un activo simple de Dagster
@asset
def my_first_asset():
    """
    Este es un activo básico de Dagster.
    Cuando se materialice, imprimirá un mensaje en la consola.
    """
    print("Ejecutando my_first_asset: ¡Hola, Dagster!")
    return "Datos de my_first_asset"

# Definir un repositorio usando Definitions (el enfoque moderno en Dagster 1.0+)
# Esto hace que el activo sea detectable por Dagit
@Definitions(
    assets=[my_first_asset],
    # Puede añadir jobs, schedules, sensors aquí también
)
def my_dagster_repository():
    return None # El objeto Definitions se devuelve implícitamente
