Guia_Ejecucion_Hive

Explicación

Esta guía configura una instancia básica de Apache Hive utilizando docker-compose. La configuración incluye dos servicios principales:

1. db: Un contenedor de PostgreSQL que actuará como la base de datos para el Metastore de Hive. Esto asegura la persistencia de los metadatos de Hive.

2. hive: Un contenedor de Hive (basado en la imagen de Bitnami) que ejecutará tanto el servicio Metastore de Hive como el HiveServer2. El servicio Hive Metastore se conectará a la base de datos PostgreSQL.

El servicio Metastore se encargará de almacenar el esquema de la base de datos y la información de la tabla. El HiveServer2 permitirá a los clientes (como Beeline, o herramientas de BI) conectarse a Hive y ejecutar consultas SQL.

Pasos para ejecutar:

1. Guarda el contenido del docker-compose.yml en un archivo llamado docker-compose.yml en tu directorio de trabajo.

2. Abre una terminal en ese directorio.

3. Ejecuta el comando provisto en runCommands para levantar los servicios.

4. Una vez que los servicios estén corriendo, puedes conectarte a HiveServer2 usando la herramienta beeline (que generalmente viene incluida con la instalación de Hive o puedes encontrarla dentro del contenedor de Hive).

Para conectarte desde tu máquina local (si tienes beeline instalado):

    beeline -u "jdbc:hive2://localhost:10000/default" -n hive -p hivepassword

Para conectarte desde dentro del contenedor de hive (si no tienes beeline localmente):

    docker exec -it <nombre_o_id_del_contenedor_hive> beeline -u "jdbc:hive2://localhost:10000/default" -n hive -p hivepassword

(Puedes obtener el nombre o ID del contenedor hive con docker ps)

Una vez conectado, puedes ejecutar comandos SQL como:

    SHOW DATABASES;
    CREATE DATABASE my_test_db;
    USE my_test_db;
    CREATE TABLE my_table (id INT, name STRING);
    SHOW TABLES;

Comandos de Ejecución

docker-compose up -d

Archivos de Configuración

docker-compose.yml

version: '2'

volumes:
  postgresql_data:
    driver: local
  hive_data:
    driver: local

services:
  db:
    image: postgres:13
    volumes:
      - 'postgresql_data:/var/lib/postgresql/data'
    environment:
      - POSTGRES_USER=hive
      - POSTGRES_PASSWORD=hivepassword
      - POSTGRES_DB=hive
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U hive -d hive"]
      interval: 5s
      timeout: 5s
      retries: 5

  hive:
    image: bitnami/hive:3.1.2
    ports:
      - '10000:10000' # HiveServer2 port
      - '9083:9083'   # Hive Metastore port
    depends_on:
      db:
        condition: service_healthy
    environment:
      - HIVE_DATABASE_HOST=db
      - HIVE_DATABASE_PORT=5432
      - HIVE_DATABASE_NAME=hive
      - HIVE_DATABASE_USER=hive
      - HIVE_DATABASE_PASSWORD=hivepassword
      - HIVE_KERBEROS_ENABLED=no # Disable Kerberos for simplicity
      # By default, bitnami/hive image runs both Metastore and HiveServer2
      # HIVE_SERVICE_TYPE=ALL is the default behaviour
    volumes:
      - 'hive_data:/bitnami/hive' # For Metastore persistent data and logs
