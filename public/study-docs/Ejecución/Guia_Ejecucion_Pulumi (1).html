Guia_Ejecucion_Pulumi

Explicación

Pulumi es una plataforma de Infraestructura como Código (IaC) que permite definir, desplegar y gestionar recursos de infraestructura en la nube utilizando lenguajes de programación reales. Esta guía te permitirá ejecutar el CLI de Pulumi dentro de un contenedor Docker/Podman, proporcionando un entorno aislado para tus proyectos Pulumi sin necesidad de instalar el CLI directamente en tu sistema host. A continuación, se detallan los pasos para configurar un contenedor con el CLI de Pulumi y un proyecto de ejemplo básico.

Pasos a seguir:

1. Guarda los archivos: Crea los siguientes archivos en tu directorio de trabajo:

  • * Dockerfile (contenido proporcionado)
  • * Crea una carpeta llamada my-pulumi-project.
  • * Dentro de my-pulumi-project, guarda Pulumi.yaml, index.ts y .gitignore (contenidos proporcionados).

2. Construye la imagen de Pulumi CLI: Ejecuta el primer comando podman build (o docker build) para crear la imagen de Docker que contendrá el CLI de Pulumi.

3. Ejecuta el contenedor e interactúa: Ejecuta el segundo comando podman run (o docker run). Esto iniciará un contenedor interactivo, montando tu directorio local my-pulumi-project en /app dentro del contenedor. Una vez dentro del contenedor, estarás en el directorio /app.

4. Inicializa y ejecuta el stack: Dentro del contenedor, ejecuta los siguientes comandos para inicializar un stack de Pulumi y previsualizar/desplegar:

  • * pulumi stack init dev
  • * pulumi up --yes

El proyecto de ejemplo index.ts simplemente exporta un mensaje; no desplegará recursos en la nube. Para desplegar recursos reales (ej. en AWS, Azure, GCP), necesitarías configurar las credenciales de tu proveedor de nube y modificar index.ts para definir esos recursos. Las credenciales se pueden pasar como variables de entorno al contenedor o configurarse con pulumi config set :region .

Comandos de Ejecución

podman build -t pulumi-cli .
podman run -it --rm -v $(pwd)/my-pulumi-project:/app pulumi-cli bash

Archivos de Configuración

Dockerfile

FROM node:18-alpine

# Establece las variables de entorno para que los comandos Pulumi estén disponibles en el PATH
ENV PATH="/root/.pulumi/bin:${PATH}"

# Instala el CLI de Pulumi
# Se usa curl para descargar el script de instalación de Pulumi
# Luego, el script se ejecuta y mueve el binario de pulumi a /root/.pulumi/bin
RUN apk add --no-cache curl unzip \
    && curl -fsSL https://get.pulumi.com/pulumi.sh | sh

# Establece el directorio de trabajo para los proyectos Pulumi
WORKDIR /app

# COMANDOS OPCIONALES:
# Si necesitas soporte para otros lenguajes (ej. Python), puedes instalarlos aquí.
# RUN apk add --no-cache python3 py3-pip

# Nota: Este Dockerfile no incluye ENTRYPOINT ni CMD por defecto
# porque la intención es que el usuario interactúe con el contenedor
# de forma interactiva (bash) y ejecute los comandos de Pulumi manualmente.

my-pulumi-project/Pulumi.yaml

name: my-pulumi-project
runtime: nodejs
description: Un proyecto mínimo de Pulumi para demostrar el uso local del CLI.

my-pulumi-project/index.ts

import * as pulumi from "@pulumi/pulumi";

// Este es un programa mínimo de Pulumi en TypeScript.
// Define una salida simple que se puede ver después de `pulumi up`.
// No se provisionan recursos reales en la nube sin configuración adicional
// y credenciales del proveedor de la nube.

// Define un valor de configuración o una constante simple
const greeting = "¡Hola, Pulumi desde el contenedor!";

// Exporta una salida del stack. Esto se mostrará en la consola después de `pulumi up`.
export const message = greeting;

// Para desplegar recursos reales, añadirías código como el siguiente:
/*
import * as aws from "@pulumi/aws";

const bucket = new aws.s3.Bucket("my-pulumi-bucket", {
    acl: "private",
    tags: {
        Environment: "Development",
        Project: "PulumiDemo",
    },
});

export const bucketName = bucket.id;
*/

// Recuerda: Para cualquier despliegue de recursos en la nube,
// necesitarías configurar tus credenciales del proveedor de la nube
// (ej. AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_REGION).
// Estas credenciales se pasarían típicamente al contenedor como variables de entorno
// o se configurarían a través de `pulumi config set aws:region us-east-1`.
