Guia_Ejecucion_Apache Iceberg

Explicación

Esta configuración proporciona un entorno local completo para trabajar con Apache Iceberg, utilizando Docker Compose para orquestar los siguientes servicios:

  • MinIO: Un servicio de almacenamiento de objetos compatible con S3 que actuará como el Data Lake donde Iceberg almacenará los datos de las tablas.
  • PostgreSQL: Una base de datos utilizada por el Hive Metastore para persistir sus metadatos.
  • Hive Metastore (HMS): El catálogo de tablas para Iceberg. Almacenará los metadatos y esquemas de las tablas Iceberg, así como de tablas Hive tradicionales si se usaran.
  • Spark Master y Worker: Un clúster de Spark configurado con las dependencias necesarias de Iceberg y S3 (para MinIO), listo para ejecutar consultas y operaciones sobre las tablas Iceberg.
  • MinIO Client: Un contenedor efímero que se encarga de crear el bucket iceberg-warehouse en MinIO, donde se almacenarán los datos de Iceberg.

Pasos para ejecutar esta configuración:

1. Guarda todos los archivos proporcionados (docker-compose.yml, Dockerfile.spark, spark-defaults.conf, minio-setup.sh) en una misma carpeta en tu sistema local.

2. Abre una terminal en esa carpeta.

3. Construye la imagen personalizada de Spark:

docker-compose build spark-master spark-worker

4. Inicia todos los servicios en segundo plano:

docker-compose up -d

5. Espera unos momentos para que todos los servicios se inicialicen, especialmente Hive Metastore y PostgreSQL.

6. Para interactuar con Iceberg, accede al contenedor spark-master:

docker-compose exec spark-master bash

7. Dentro del contenedor de Spark, puedes iniciar una sesión de pyspark o spark-sql (ya preconfigurada con Iceberg, HMS y MinIO):

/opt/bitnami/spark/bin/pyspark

o para SQL puro:

/opt/bitnami/spark/bin/spark-sql

8. Ahora puedes crear y manipular tablas Iceberg. Por ejemplo, en pyspark:

spark.sql("CREATE NAMESPACE IF NOT EXISTS hive_prod.default_db").show()
spark.sql("CREATE TABLE hive_prod.default_db.my_iceberg_table (id BIGINT, name STRING) USING iceberg").show()
spark.sql("INSERT INTO hive_prod.default_db.my_iceberg_table VALUES (1, 'Alice'), (2, 'Bob')").show()
spark.sql("SELECT * FROM hive_prod.default_db.my_iceberg_table").show()

Para detener y limpiar:

  • Detener los servicios: docker-compose down
  • Detener y eliminar volúmenes (borrar datos persistentes): docker-compose down -v

Archivos de Configuración

Dockerfile.spark

# Usa una imagen base de Spark con soporte para Python.
# bitnami/spark es una buena opción ya que viene con Java y Spark preconfigurados.
FROM bitnami/spark:3.5.0

USER root

# Copia la configuración de Spark, que incluirá la configuración del Metastore de Hive y S3,
# y también especificará las dependencias del runtime de Iceberg para Spark.
COPY spark-defaults.conf /opt/bitnami/spark/conf/spark-defaults.conf

# Vuelve al usuario no-root (1001 es común para las imágenes de Bitnami)
USER 1001

docker-compose.yml

version: '3.8'

services:
  minio:
    image: minio/minio:latest
    ports:
      - "9000:9000"
      - "9001:9001" # Consola de MinIO
    environment:
      MINIO_ROOT_USER: minioadmin
      MINIO_ROOT_PASSWORD: minioadmin
      MINIO_SERVER_URL: http://minio:9000 # Para comunicación interna en la red
    command: server /data --console-address ":9001"
    volumes:
      - minio_data:/data # Persistir datos
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:9000/minio/health/live"]
      interval: 30s
      timeout: 20s
      retries: 3
    networks:
      - iceberg-net

  minio-client:
    image: minio/mc:latest # Imagen del cliente MinIO
    entrypoint: /bin/sh -c "./minio-setup.sh"
    volumes:
      - ./minio-setup.sh:/minio-setup.sh
    environment:
      MINIO_HOST: minio
      MINIO_PORT: 9000
      MINIO_ROOT_USER: minioadmin
      MINIO_ROOT_PASSWORD: minioadmin
    depends_on:
      minio:
        condition: service_healthy
    networks:
      - iceberg-net
    restart: "no" # Asegura que no se siga ejecutando después de completar su tarea

  db:
    image: postgres:13
    environment:
      POSTGRES_DB: metastore
      POSTGRES_USER: hive
      POSTGRES_PASSWORD: hive
    volumes:
      - pg_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U hive -d metastore"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - iceberg-net

  hive-metastore:
    image: apache/hive-metastore:3.1.2 # Imagen dedicada del Hive Metastore
    ports:
      - "9083:9083"
    environment:
      # Configuración para conectarse a PostgreSQL
      METASTORE_DB_HOSTNAME: db
      METASTORE_DB_PORT: 5432
      METASTORE_DB_NAME: metastore
      METASTORE_DB_USER: hive
      METASTORE_DB_PASSWORD: hive
      # Inicializar esquema en la primera ejecución
      METASTORE_SCHEMA_VERIFICATION: false
      METASTORE_DETACH_JVM: true # Ejecutar en primer plano
    depends_on:
      db:
        condition: service_healthy
      minio-client: # Esperar a que el bucket de MinIO se haya creado
        condition: service_completed_successfully
    networks:
      - iceberg-net

  spark-master:
    build:
      context: .
      dockerfile: Dockerfile.spark
    hostname: spark-master
    environment:
      SPARK_MODE: master
      SPARK_RPC_AUTHENTICATION_ENABLED: "false"
      SPARK_RPC_ENCRYPTION_ENABLED: "false"
      SPARK_LOCAL_STORAGE_ENCRYPTION_ENABLED: "false"
      SPARK_UI_PORT: 8080
      SPARK_MASTER_WEBUI_PORT: 8080
    ports:
      - "8080:8080" # UI de Spark Master
      - "7077:7077" # Puerto interno de Spark Master
    volumes:
      - ./spark-defaults.conf:/opt/bitnami/spark/conf/spark-defaults.conf
    depends_on:
      minio:
        condition: service_healthy
      hive-metastore:
        condition: service_started # HMS debe estar corriendo
    networks:
      - iceberg-net

  spark-worker:
    build:
      context: .
      dockerfile: Dockerfile.spark
    hostname: spark-worker-${HOSTNAME}
    environment:
      SPARK_MODE: worker
      SPARK_MASTER_URL: spark://spark-master:7077
      SPARK_WORKER_CORES: 1
      SPARK_WORKER_MEMORY: 1G
      SPARK_RPC_AUTHENTICATION_ENABLED: "false"
      SPARK_RPC_ENCRYPTION_ENABLED: "false"
      SPARK_LOCAL_STORAGE_ENCRYPTION_ENABLED: "false"
    depends_on:
      spark-master:
        condition: service_started
    networks:
      - iceberg-net

volumes:
  minio_data:
  pg_data:

networks:
  iceberg-net:
    driver: bridge

spark-defaults.conf

# --- Configuración de Iceberg y Hive Metastore ---
# Agrega las extensiones SQL de Iceberg a Spark
spark.sql.extensions=org.apache.iceberg.spark.extensions.IcebergSparkSessionExtensions

# Configura un catálogo de Spark para Iceberg, apuntando al Hive Metastore
# 'hive_prod' es el nombre del catálogo que usarás en Spark SQL, por ejemplo, 'USE hive_prod.default_db;'
spark.sql.catalog.hive_prod=org.apache.iceberg.spark.SparkSessionCatalog
spark.sql.catalog.hive_prod.type=hive
spark.sql.catalog.hive_prod.uri=thrift://hive-metastore:9083
spark.sql.catalog.hive_prod.warehouse=s3a://iceberg-warehouse/

# También configura un catálogo Hive simple si quieres interactuar con tablas Hive regulares
spark.hadoop.hive.metastore.uris=thrift://hive-metastore:9083

# --- Configuración de S3 (MinIO) ---
# Establece el endpoint S3 a MinIO
spark.hadoop.fs.s3a.endpoint=http://minio:9000
# Habilita el acceso estilo ruta para MinIO
spark.hadoop.fs.s3a.path.style.access=true
# Credenciales de MinIO
spark.hadoop.fs.s3a.access.key=minioadmin
spark.hadoop.fs.s3a.secret.key=minioadmin
# Proveedor de credenciales para S3A
spark.hadoop.fs.s3a.aws.credentials.provider=org.apache.hadoop.fs.s3a.SimpleAWSCredentialsProvider
spark.hadoop.fs.s3a.impl=org.apache.hadoop.fs.s3a.S3AFileSystem

# --- Dependencias de Spark ---
# Agrega las dependencias de Iceberg Spark runtime y el paquete Hadoop AWS (S3A)
# Asegúrate de que las versiones coincidan con tu versión de Spark y las librerías de Iceberg
spark.jars.packages=org.apache.iceberg:iceberg-spark-runtime-3.5_2.12:1.4.0,org.apache.hadoop:hadoop-aws:3.3.2,com.amazonaws:aws-java-sdk-bundle:1.11.1026

# --- Configuraciones opcionales de Spark ---
spark.driver.memory=2g
spark.executor.memory=2g
spark.executor.cores=1
spark.cores.max=2
spark.sql.shuffle.partitions=2
spark.sql.warehouse.dir=s3a://iceberg-warehouse/

minio-setup.sh

#!/bin/sh
# minio-setup.sh
# Configura las credenciales de mc para MinIO
/usr/bin/mc alias set myminio http://${MINIO_HOST}:${MINIO_PORT} ${MINIO_ROOT_USER} ${MINIO_ROOT_PASSWORD}

echo "Waiting for MinIO to be ready..."
# Espera a que MinIO esté disponible y responda a 'mc ls'
until /usr/bin/mc ls myminio > /dev/null 2>&1; do
  sleep 1
done

# Define el nombre del bucket para el warehouse de Iceberg
ICEBERG_WAREHOUSE_BUCKET="iceberg-warehouse"

# Crea el bucket si no existe
if ! /usr/bin/mc ls myminio/${ICEBERG_WAREHOUSE_BUCKET} > /dev/null 2>&1; then
  echo "Creating bucket '${ICEBERG_WAREHOUSE_BUCKET}'..."
  /usr/bin/mc mb myminio/${ICEBERG_WAREHOUSE_BUCKET}
  echo "Bucket '${ICEBERG_WAREHOUSE_BUCKET}' created."
else
  echo "Bucket '${ICEBERG_WAREHOUSE_BUCKET}' already exists."
fi

# Nota: No se requiere configurar políticas de acceso adicionales para este setup local,
# ya que Spark se autenticará con las credenciales de MinIO.
