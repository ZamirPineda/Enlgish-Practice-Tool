Guia_Ejecucion_Cilium

Explicación

Esta guía práctica te permitirá levantar un clúster local de Kubernetes usando Kind (Kubernetes in Docker/Podman) y luego instalar Cilium como su solución de red (CNI) y seguridad. Cilium aprovecha eBPF para proporcionar redes de alta eficiencia, visibilidad y aplicación de políticas de seguridad. Se configurará para reemplazar el kube-proxy de Kubernetes y se habilitará Hubble para una visibilidad profunda del tráfico de red. Antes de comenzar, asegúrate de tener instalados kind, helm y kubectl.

Comandos de Ejecución

# 1. Crear un clúster de Kubernetes local con Kind\n#    Este paso creará un clúster de un solo nodo en tu entorno Docker o Podman.\n#    Para usar Podman, puedes ejecutar: KIND_EXPERIMENTAL_PROVIDER=podman kind create cluster --config kind-config.yaml\nkind create cluster --config kind-config.yaml\n\n# 2. Obtener la IP del nodo de control-plane de Kind\n#    Esta IP es necesaria para configurar Cilium en modo 'kubeProxyReplacement=strict'.\n#    Si usas Podman, reemplaza 'docker inspect' con 'podman inspect'.\nKIND_CONTROL_PLANE_IP=$(docker inspect -f '{{ .NetworkSettings.IPAddress }}' cilium-cluster-control-plane)\n\n# 3. Configurar Helm y agregar el repositorio de Cilium\nhelm repo add cilium https://helm.cilium.io/\nhelm repo update\n\n# 4. Instalar Cilium en el clúster usando Helm\n#    Se configura Cilium para reemplazar completamente kube-proxy ('strict' mode).\n#    Se habilita Hubble (UI, Relay y Metrics) para la observabilidad de la red.\n#    Asegúrate de que la versión de Cilium sea compatible con tu versión de Kubernetes en Kind.\n#    (ej. 1.15.x para K8s 1.28/1.29)\nhelm install cilium cilium/cilium --namespace kube-system --set global.kubeProxyReplacement=strict --set global.k8sServiceHost=${KIND_CONTROL_PLANE_IP} --set global.k8sServicePort=6443 --set global.hubble.enabled=true --set global.hubble.ui.enabled=true --set global.hubble.relay.enabled=true --set global.hubble.metrics.enable='{dns,drop,tcp,flow,port-distribution,icmp,http}' --version 1.15.4 # Especifica una versión de Cilium (puedes verificar las últimas versiones en la doc oficial)\n\n# 5. Verificar el estado del despliegue de Cilium y Hubble\necho \"Esperando que Cilium se despliegue...\"\nkubectl -n kube-system rollout status ds/cilium --timeout=300s\nkubectl -n kube-system rollout status deployment/cilium-operator --timeout=300s\nkubectl -n kube-system rollout status deployment/hubble-ui --timeout=300s\nkubectl -n kube-system rollout status deployment/hubble-relay --timeout=300s\n\n# 6. Acceder a la interfaz de usuario de Hubble\necho \"\\nPara acceder a Hubble UI:\"\necho \"Ejecuta: kubectl port-forward -n kube-system service/hubble-ui 8080:80\"\necho \"Luego abre http://localhost:8080 en tu navegador.\\n\"\n\n# 7. Acceder a los logs de Cilium\necho \"Para acceder a los logs de Cilium (ejemplo de un pod):\"\necho \"kubectl logs -n kube-system -l k8s-app=cilium --tail=50\"\n

Archivos de Configuración

kind-config.yaml

kind: Cluster\napiVersion: kind.x-k8s.io/v1alpha4\nname: cilium-cluster\nnodes:\n- role: control-plane\n  # Configuración opcional para mapear puertos del host al contenedor del clúster.\n  # Útil si planeas desplegar aplicaciones que necesiten ser accesibles desde el host.\n  extraPortMappings:\n  - containerPort: 80\n    hostPort: 80\n    listenAddress: \"127.0.0.1\"\n    protocol: tcp\n  - containerPort: 443\n    hostPort: 443\n    listenAddress: \"127.0.0.1\"\n    protocol: tcp\n
