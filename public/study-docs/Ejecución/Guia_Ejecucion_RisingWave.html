Guia_Ejecucion_RisingWave

Explicación

Esta guía te ayudará a levantar una instancia básica de RisingWave, un motor de streaming SQL distribuido, utilizando docker-compose. RisingWave permite procesar y analizar flujos de datos en tiempo real de manera eficiente y es compatible con el protocolo PostgreSQL.

La configuración incluye los componentes esenciales de RisingWave:

  • meta-node: Gestiona el metadata del clúster.
  • compute-node: Realiza el procesamiento y cómputo de datos.
  • frontend: Expone una interfaz compatible con PostgreSQL para que puedas ejecutar consultas SQL.
  • compactor: Se encarga de la compactación de los datos de estado para optimizar el almacenamiento y el rendimiento.

Se proporciona un Dockerfile para construir una imagen de cliente psql básica, que será útil para interactuar con RisingWave una vez que esté en funcionamiento.

Pasos a seguir:

1. Guarda los archivos: Crea un directorio de proyecto (ej. risingwave-local) y guarda docker-compose.yml y Dockerfile (para el cliente psql) en ese directorio.

2. Construye la imagen del cliente (opcional, pero recomendado): Navega hasta el directorio y ejecuta:

    docker build -t psql-client -f Dockerfile .

3. Inicia los servicios de RisingWave: Ejecuta el comando docker-compose up -d. Esto descargará las imágenes oficiales de RisingWave y levantará todos los servicios en segundo plano.

4. Verifica el estado: Puedes verificar que los contenedores están funcionando con docker-compose ps.

5. Conéctate a RisingWave: Una vez que el frontend esté listo (puede tardar unos segundos en inicializarse), puedes conectar usando el cliente psql que construiste. El frontend de RisingWave escucha en el puerto 4566 y el usuario por defecto es root con la base de datos dev.

  • * Para conectar desde tu máquina local (host):
        docker run -it --rm --network host psql-client -h localhost -p 4566 -U root -d dev

Nota: La opción --network host permite que el contenedor psql-client vea localhost en tu máquina anfitriona, que está mapeada al puerto 4566 del frontend de RisingWave. Si prefieres usar la red de docker-compose, deberías agregar el cliente psql como un servicio más en el docker-compose.yml.

Una vez conectado, puedes probar consultas SQL como CREATE SOURCE, CREATE MATERIALIZED VIEW, etc. Por ejemplo:

    CREATE TABLE t1 (v1 int); 
    INSERT INTO t1 VALUES (1), (2), (3);
    SELECT * FROM t1;

6. Detén y limpia los servicios: Cuando hayas terminado, puedes detener y eliminar los contenedores y la red con:

    docker-compose down

Comandos de Ejecución

docker-compose up -d

Archivos de Configuración

Dockerfile

# Dockerfile para un cliente PostgreSQL básico para conectar a RisingWave.
# RisingWave expone una interfaz compatible con PostgreSQL.

# Usa una imagen base ligera con herramientas comunes.
FROM debian:bookworm-slim

# Instala el cliente PostgreSQL. Incluye 'netcat' para healthchecks si fuera necesario en otros contextos.
# Se usa 'apt-get update' y 'apt-get install -y' para asegurar que el cliente psql está disponible.
RUN apt-get update && \
    apt-get install -y --no-install-recommends postgresql-client netcat-traditional && \
    rm -rf /var/lib/apt/lists/*

# Establece el punto de entrada para que el contenedor pueda ser usado para ejecutar comandos psql.
# Esto hace que 'docker run -it psql-client' directamente entre en el shell psql o permite pasar comandos.
ENTRYPOINT ["psql"]

# Comando por defecto, si no se especifica ninguno, puede ser para mostrar la ayuda o conectar.
# Es buena práctica dejarlo vacío o algo simple si el ENTRYPOINT es el comando principal.
CMD ["--help"]

# Para conectar a RisingWave, se usará:
# docker run -it --rm --network host psql-client -h localhost -p 4566 -U root -d dev

docker-compose.yml

version: '3.8'
services:
  meta-node:
    image: risingwave/risingwave:latest
    command: rw meta-node --listen-addr 0.0.0.0:5690 --advertise-addr meta-node:5690
    ports:
      - "5690:5690" # Puerto para comunicación interna del meta node
    healthcheck:
      test: ["CMD", "nc", "-z", "localhost", "5690"]
      interval: 5s
      timeout: 3s
      retries: 5

  compute-node:
    image: risingwave/risingwave:latest
    command: rw compute-node --listen-addr 0.0.0.0:5688 --advertise-addr compute-node:5688 --meta-node-addr meta-node:5690
    depends_on:
      meta-node:
        condition: service_healthy
    ports:
      - "5688:5688" # Puerto para comunicación interna del compute node
    healthcheck:
      test: ["CMD", "nc", "-z", "localhost", "5688"]
      interval: 5s
      timeout: 3s
      retries: 5

  frontend:
    image: risingwave/risingwave:latest
    command: rw frontend --listen-addr 0.0.0.0:4566 --advertise-addr frontend:4566 --meta-node-addr meta-node:5690
    depends_on:
      meta-node:
        condition: service_healthy
    ports:
      - "4566:4566" # Puerto compatible con PostgreSQL para conexión de clientes
    healthcheck:
      test: ["CMD", "nc", "-z", "localhost", "4566"]
      interval: 5s
      timeout: 3s
      retries: 5

  compactor:
    image: risingwave/risingwave:latest
    command: rw compactor --listen-addr 0.0.0.0:6660 --advertise-addr compactor:6660 --meta-node-addr meta-node:5690
    depends_on:
      meta-node:
        condition: service_healthy
    ports:
      - "6660:6660" # Puerto para comunicación interna del compactor
    healthcheck:
      test: ["CMD", "nc", "-z", "localhost", "6660"]
      interval: 5s
      timeout: 3s
      retries: 5
