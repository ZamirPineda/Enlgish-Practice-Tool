Guia_Ejecucion_pgvector

Explicación

Esta guía le permitirá configurar y ejecutar una instancia local de PostgreSQL con la extensión pgvector utilizando Podman o Docker. Se creará una imagen de Docker personalizada que incluye la extensión pgvector compilada desde su fuente, y se inicializará una base de datos con la extensión habilitada y una tabla de ejemplo.

Pasos a seguir:

1. Crear el Dockerfile: Este archivo (Dockerfile) define cómo construir la imagen de PostgreSQL con pgvector. Clona el repositorio de pgvector, lo compila y lo instala.

2. Crear el archivo init.sql: Este script se ejecutará automáticamente la primera vez que se inicie el contenedor de PostgreSQL. Creará una base de datos llamada vectordb, habilitará la extensión vector dentro de ella y creará una tabla items con una columna embedding de tipo vector(3) junto con algunos datos de ejemplo.

3. Construir y ejecutar el contenedor: El comando runCommands se encarga de estos dos pasos:

  • * podman build -t pgvector-db .: Construye la imagen de Docker/Podman con el tag pgvector-db usando el Dockerfile en el directorio actual.
  • * podman run ...: Inicia un contenedor a partir de la imagen recién creada. Mapea el puerto 5432 del host al contenedor, establece las credenciales de la base de datos (pguser, pgpassword, vectordb) y monta el archivo init.sql para la inicialización automática.

Una vez que el contenedor esté en funcionamiento, podrá conectarse a la base de datos vectordb usando las credenciales proporcionadas y verificar que la extensión pgvector esté instalada y funcionando.

Comandos de Ejecución

podman build -t pgvector-db . && podman run --name pgvector-instance -e POSTGRES_USER=pguser -e POSTGRES_PASSWORD=pgpassword -e POSTGRES_DB=vectordb -p 5432:5432 -v "$(pwd)/init.sql:/docker-entrypoint-initdb.d/init.sql" -d pgvector-db

Archivos de Configuración

Dockerfile

# Usa una imagen base de PostgreSQL. Alpine es ligera y reduce el tamaño final de la imagen.
FROM postgres:16-alpine

# Instala las herramientas necesarias para compilar pgvector.
# build-base incluye make y gcc. postgresql-dev proporciona los headers de desarrollo de PostgreSQL.
# git es necesario para clonar el repositorio de pgvector.
RUN apk add --no-cache build-base postgresql-dev git

# Clona el repositorio de pgvector. Usa una versión específica para mayor estabilidad.
# La versión 0.6.0 es una de las más recientes y estables en el momento de escribir esto.
# Clona el repositorio en /usr/src/pgvector.
RUN git clone --branch v0.6.0 https://github.com/pgvector/pgvector.git /usr/src/pgvector

# Compila e instala pgvector.
# Cambia al directorio del código fuente de pgvector.
WORKDIR /usr/src/pgvector
# Ejecuta 'make' para compilar la extensión.
RUN make
# Ejecuta 'make install' para instalar la extensión en el sistema de PostgreSQL.
RUN make install

# Limpia las herramientas de compilación y los archivos fuente para reducir el tamaño de la imagen.
# Vuelve al directorio raíz.
WORKDIR /
# Elimina los paquetes de compilación y el repositorio git clonado.
RUN apk del build-base postgresql-dev git && \
    rm -rf /usr/src/pgvector

# El puerto por defecto de PostgreSQL es 5432. Lo exponemos para la comunicación externa.
EXPOSE 5432

# La imagen base de PostgreSQL está configurada para ejecutar automáticamente scripts
# SQL o shell ubicados en /docker-entrypoint-initdb.d/ al iniciar por primera vez el contenedor.
# Esto se utilizará con un volumen montado para el archivo 'init.sql'.

init.sql

-- Este script se ejecutará automáticamente cuando el contenedor de PostgreSQL inicie por primera vez
-- gracias al mapeo de volumen a /docker-entrypoint-initdb.d/init.sql.

-- Se conectará a la base de datos 'vectordb' que se crea automáticamente por la imagen de PostgreSQL
-- usando la variable de entorno POSTGRES_DB.

-- Habilita la extensión 'vector'. Esto hará que los tipos de datos VECTOR estén disponibles.
-- Si la base de datos no es 'vectordb', el usuario deberá ajustar el comando de conexión
-- o especificar la base de datos con -d en psql.
CREATE EXTENSION IF NOT EXISTS vector;

-- Crea una tabla de ejemplo con una columna de tipo VECTOR.
CREATE TABLE IF NOT EXISTS items (
    id bigserial PRIMARY KEY,
    embedding vector(3) -- Define una columna para almacenar vectores de 3 dimensiones
);

-- Inserta algunos datos de ejemplo si la tabla está vacía.
DO $$
BEGIN
    IF NOT EXISTS (SELECT 1 FROM items WHERE embedding = '[1,2,3]') THEN
        INSERT INTO items (embedding) VALUES ('[1,2,3]'), ('[4,5,6]'), ('[7,8,9]');
    END IF;
END
$$;

-- Opcional: crea un índice para búsquedas de similitud (ej. usando IVFFlat).
-- Esto requiere una versión reciente de pgvector y un tamaño mínimo de tabla para que sea eficiente.
-- Descomentar y ajustar 'lists' según el tamaño esperado de su tabla.
-- CREATE INDEX IF NOT EXISTS ON items USING ivfflat (embedding vector_l2_ops) WITH (lists = 100);

-- Muestra los datos insertados para verificar.
SELECT * FROM items;

-- Muestra las extensiones instaladas para confirmar que 'vector' está presente.
SELECT * FROM pg_extension WHERE extname = 'vector';
