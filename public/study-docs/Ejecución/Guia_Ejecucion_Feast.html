Guia_Ejecucion_Feast

Explicación

Esta guía le permitirá configurar y ejecutar una instancia básica de Feast localmente utilizando Docker Compose. Feast es un almacén de características (Feature Store) que le ayuda a gestionar y servir características para modelos de aprendizaje automático. Esta configuración incluye:

  • Redis: Como almacén en línea (online store) para servir características con baja latencia.
  • Feast Application: Un contenedor que contendrá el SDK de Feast, el registro local de características (registry) y los archivos de definición de características. Este contenedor realizará las operaciones de feast apply y ejecutará un script de ejemplo para mostrar la obtención de características históricas y en línea.
  • Offline Store: Para simplificar, utilizaremos archivos Parquet locales como almacén fuera de línea (offline store).

Pasos a seguir:

1. Preparación de archivos:

  • * Guarde el contenido de docker-compose.yml, Dockerfile, feature_store.yaml, start_feast.sh y generate_data.py en el directorio raíz de su proyecto.
  • * Cree un directorio llamado feature_repo en el mismo directorio raíz y guarde example.py dentro de feature_repo.
  • * Cree un directorio llamado data en el mismo directorio raíz.

2. Generar datos de ejemplo:

  • * Ejecute el script generate_data.py localmente (no en un contenedor) para crear el archivo data/data.parquet necesario para el almacén fuera de línea:

python generate_data.py

3. Iniciar los contenedores:

  • * Desde el directorio raíz de su proyecto (donde se encuentran docker-compose.yml y los demás archivos), ejecute el comando docker-compose up -d.

4. Verificar el estado:

  • * Puede observar los logs del contenedor feast_app para ver la inicialización de Feast y la ejecución del script de ejemplo:

docker-compose logs -f feast_app

  • * Debería ver la aplicación de las definiciones de características, la recuperación de características históricas y en línea.

5. Detener los contenedores:

  • * Para detener y eliminar los contenedores, redes y volúmenes creados por Docker Compose, ejecute:

docker-compose down -v

Esta configuración le proporciona un entorno funcional para experimentar con Feast de forma local.

Comandos de Ejecución

docker-compose up -d

Archivos de Configuración

Dockerfile

FROM python:3.9-slim-buster

WORKDIR /app

# Install Feast and Redis client
RUN pip install "feast[redis]" pandas pyarrow

# Copy necessary files for the app root
COPY feature_store.yaml .
COPY start_feast.sh .

# Create feature_repo directory and copy feature definitions
RUN mkdir -p feature_repo
COPY feature_repo/example.py feature_repo/example.py

# Ensure scripts are executable
RUN chmod +x start_feast.sh

# Environment variables (can be overridden by docker-compose)
ENV REDIS_HOST=redis
ENV REDIS_PORT=6379

# Default command to run
CMD ["/bin/bash", "start_feast.sh"]

docker-compose.yml

version: '3.8'
services:
  redis:
    image: redis:6-alpine
    container_name: feast_redis
    ports:
      - "6379:6379"
    command: redis-server --appendonly yes
    volumes:
      - redis_data:/data

  feast_app:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: feast_app
    volumes:
      - ./data:/app/data
      - ./feature_repo:/app/feature_repo
      - ./feature_store.yaml:/app/feature_store.yaml
      - ./start_feast.sh:/app/start_feast.sh
    depends_on:
      - redis
    environment:
      - REDIS_HOST=redis
      - REDIS_PORT=6379
    entrypoint: ["/bin/bash", "/app/start_feast.sh"]

volumes:
  redis_data:

feature_store.yaml

project: my_feature_project
registry: data/registry.db # Local file for registry within the container
provider: local
online_store:
    type: redis
    host: redis
    port: 6379
# offline_store will default to local files (parquet) because of 'provider: local'

start_feast.sh

#!/bin/bash

# Ensure the data directory (and thus registry path) exists inside the container
mkdir -p data

echo "Applying feature definitions to local registry..."
# Feast expects feature_store.yaml in the repo_path. 
# Since the Dockerfile copies feature_store.yaml to /app, 
# and we are running from WORKDIR /app, the repository root is "."
feast apply --feature-repo .

echo "Feast setup complete. Running example script..."
# Run the example Python script from its location (feature_repo/example.py)
python feature_repo/example.py

echo "To stop: docker-compose down -v"
# Keep the container running for inspection
tail -f /dev/null

feature_repo/example.py

import pandas as pd
from datetime import datetime, timedelta
from feast import FeatureStore, Entity, FeatureView, Field, FileSource, ValueType
from feast.types import Int64, Float32

# Define an entity
user = Entity(name="user_id", description="ID of the user", value_type=ValueType.INT64)

# Define a FileSource for the offline store
# This assumes data.parquet exists with 'user_id', 'feature1', 'feature2', 'event_timestamp'
file_source = FileSource(
    path="/app/data/data.parquet", # Path inside the container, mounted from host
    timestamp_field="event_timestamp",
)

# Define a FeatureView
user_feature_view = FeatureView(
    name="user_features",
    entities=[user],
    ttl=timedelta(days=1), # Time-to-live for online store entries
    schema=[
        Field(name="feature1", dtype=Float32),
        Field(name="feature2", dtype=Int64),
    ],
    source=file_source,
)

# Initialize a FeatureStore
# The repo_path should point to the directory containing feature_store.yaml and feature definitions.
# Since feature_store.yaml is at /app and example.py is run from /app, '.' is correct.
store = FeatureStore(repo_path=".")

print("\n--- Retrieving historical features ---")
# Create an entity_df for historical feature retrieval
entity_df = pd.DataFrame.from_dict(
    {
        "event_timestamp": [datetime.now() - timedelta(hours=2)], # Request features at a specific point in time
        "user_id": [1001], # For user_id 1001
    }
)

historical_features = store.get_historical_features(
    entity_df=entity_df,
    features=["user_features:feature1", "user_features:feature2"],
).to_df()

print("Historical features retrieved:")
print(historical_features)

print("\n--- Retrieving online features ---")
# For online features, we typically need to materialize data first. 
# For simplicity in this example, if the feature is not materialized, 
# Feast might return default values or raise an error depending on configuration.
# A full materialization command would look like:
# feast materialize-incremental 2023-01-01T00:00:00 2023-01-01T23:59:59 --feature-repo .
# However, for a basic demo, we'll try to retrieve. Redis might be empty if not explicitly materialized.

online_features = store.get_online_features(
    features=["user_features:feature1", "user_features:feature2"],
    entity_rows=[{"user_id": 1001}],
).to_dict()

print("Online features retrieved (may be empty if not materialized):")
print(online_features)

print("\nFeast demonstration complete!")

generate_data.py

import pandas as pd
from datetime import datetime, timedelta
import os

# Define the output directory and filename
output_dir = "data"
output_file = os.path.join(output_dir, "data.parquet")

# Create the output directory if it doesn't exist
os.makedirs(output_dir, exist_ok=True)

# Sample data
now = datetime.now()
data = {
    "event_timestamp": [
        now - timedelta(days=2),
        now - timedelta(days=1),
        now - timedelta(hours=12),
        now - timedelta(hours=1),
        now - timedelta(minutes=30)
    ],
    "user_id": [1001, 1002, 1001, 1003, 1001],
    "feature1": [10.5, 12.3, 11.0, 15.1, 11.5],
    "feature2": [100, 200, 105, 300, 110],
}
df = pd.DataFrame(data)

# Save to parquet
df.to_parquet(output_file, index=False)

print(f"Generated dummy data at: {output_file}")
print("Content of data.parquet:")
print(df)
