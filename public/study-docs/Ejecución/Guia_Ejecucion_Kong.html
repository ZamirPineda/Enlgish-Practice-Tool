Guia_Ejecucion_Kong

Explicación

Esta guía te permitirá levantar una instancia básica de Kong Gateway con PostgreSQL como base de datos usando docker-compose. Kong es un API Gateway y una plataforma de gestión de microservicios que te permite gestionar, autenticar y monitorizar tus APIs y microservicios.nnPasos para la configuración y ejecución:nn1. Guarda el archivo docker-compose.yml: Crea un archivo llamado docker-compose.yml en un directorio de tu elección y copia el contenido proporcionado en la sección supportFiles.nn2. Inicia los servicios: Abre tu terminal en el mismo directorio donde guardaste docker-compose.yml y ejecuta el comando docker-compose up -d. Esto iniciará los contenedores de PostgreSQL y Kong en segundo plano.nn3. Espera a que los servicios estén listos: Los servicios de kong-database y kong-gateway tienen healthchecks configurados, lo que significa que docker-compose esperará a que PostgreSQL esté listo antes de iniciar Kong, y a que Kong esté listo antes de considerarlo saludable. Esto puede tomar unos segundos.nn4. Inicializa la base de datos de Kong: Una vez que los contenedores estén funcionando, necesitas ejecutar las migraciones de la base de datos de Kong. Ejecuta el siguiente comando para inicializar el esquema de la base de datos dentro del contenedor de Kong:n docker-compose exec kong-gateway kong migrations bootstrapnn5. Verifica la instalación:n * Puedes acceder a la Admin API de Kong en http://localhost:8001.n * El Proxy de Kong (donde tus APIs estarán expuestas) estará disponible en http://localhost:8000 para HTTP y https://localhost:8443 para HTTPS.nnPara detener los servicios, simplemente ejecuta docker-compose down en el mismo directorio.

Comandos de Ejecución

docker-compose up -d

Archivos de Configuración

docker-compose.yml

version: "3.9"

services:
  kong-database:
    image: postgres:9.6 # Versión estable de PostgreSQL
    container_name: kong-database
    environment:
      POSTGRES_DB: kong
      POSTGRES_USER: kong
      POSTGRES_PASSWORD: kong
    volumes:
      - kong_data:/var/lib/postgresql/data # Persistencia de datos para PostgreSQL
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U kong -d kong"]
      interval: 10s
      timeout: 5s
      retries: 5
    restart: on-failure

  kong-gateway:
    image: kong:latest # Imagen oficial de Kong Gateway
    container_name: kong-gateway
    environment:
      KONG_DATABASE: postgres
      KONG_PG_HOST: kong-database # Nombre del servicio de PostgreSQL en docker-compose
      KONG_PG_USER: kong
      KONG_PG_PASSWORD: kong
      KONG_PG_DATABASE: kong
      KONG_ADMIN_LISTEN: 0.0.0.0:8001, 0.0.0.0:8444 ssl # Puertos para la API de administración de Kong
      KONG_PROXY_LISTEN: 0.0.0.0:8000, 0.0.0.0:8443 ssl # Puertos para el proxy de Kong (tráfico de API)
    ports:
      - "8000:8000/tcp" # Mapeo para el tráfico HTTP del proxy
      - "8443:8443/tcp" # Mapeo para el tráfico HTTPS del proxy
      - "8001:8001/tcp" # Mapeo para la Admin API HTTP
      - "8444:8444/tcp" # Mapeo para la Admin API HTTPS
    depends_on:
      kong-database:
        condition: service_healthy # Asegura que la base de datos esté saludable antes de iniciar Kong
    restart: on-failure
    healthcheck:
      test: ["CMD-SHELL", "kong health"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  kong_data: # Define el volumen para la persistencia de datos de PostgreSQL
