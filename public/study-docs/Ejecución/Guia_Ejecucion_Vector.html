Guía Rápida para Ejecutar Vector Localmente

Esta guía te permitirá configurar y ejecutar una instancia básica de [Vector](https://vector.dev/), un agente de datos de observabilidad de alto rendimiento, utilizando Podman o Docker. La configuración provista hará que Vector monitoree un archivo de log (dummy.log) en tu sistema local y envíe su contenido, transformado a formato JSON, directamente a la consola (stdout) del contenedor.

#### Pasos a Seguir:

1. Crea los archivos necesarios:

  • * Guarda el contenido del Dockerfile en un archivo llamado Dockerfile.
  • * Guarda el contenido de vector.toml en un archivo llamado vector.toml.
  • * Crea un directorio llamado logs en el mismo nivel que Dockerfile y vector.toml.
  • * Dentro del directorio logs, guarda el contenido de logs/dummy.log en un archivo llamado dummy.log.

La estructura de tu directorio debería ser algo así:

    .
    ├── Dockerfile
    ├── vector.toml
    └── logs/
        └── dummy.log

2. Construye la imagen de Docker/Podman:

Ejecuta el primer comando de runCommands para construir la imagen. Puedes reemplazar podman con docker si lo prefieres.

3. Ejecuta el contenedor de Vector:

Ejecuta el segundo comando de runCommands para iniciar el contenedor. Este comando iniciará el contenedor, montará tu directorio logs local en el contenedor y cargará la configuración de Vector.

4. Verifica la salida:

Una vez que el contenedor esté en ejecución, usa el siguiente comando para ver la salida de Vector: 

    podman logs -f vector-instance
    # O si usas Docker:
    # docker logs -f vector-instance

Deberías ver las líneas del dummy.log procesadas y mostradas en formato JSON.

5. Prueba la reactividad (Opcional):

Mientras podman logs -f (o docker logs -f) está en ejecución, puedes añadir nuevas líneas al archivo logs/dummy.log en tu sistema host. Por ejemplo: 

    echo '{"timestamp": "2023-10-27T10:00:15Z", "level": "INFO", "message": "New log entry!"}' >> logs/dummy.log

Vector debería detectar los cambios y mostrar las nuevas líneas en la consola del contenedor.

6. Detén y elimina el contenedor (cuando termines): 

    podman stop vector-instance
    podman rm vector-instance
    # O si usas Docker:
    # docker stop vector-instance
    # docker rm vector-instance

Comandos de Ejecución

podman build -t my-vector-instance . && podman run -d --name vector-instance -v $(pwd)/logs:/var/log/app my-vector-instance

Archivos de Configuración

Dockerfile

# Usa la imagen oficial de Vector como base.
# Se elige una versión específica y una variante Alpine para un tamaño más pequeño y eficiencia.
FROM timberio/vector:0.35.0-alpine

# Establece el directorio de trabajo dentro del contenedor donde se gestionarán los archivos de configuración.
WORKDIR /etc/vector

# Copia el archivo de configuración de Vector `vector.toml` desde el sistema host al contenedor.
# Este archivo define cómo Vector recolectará, transformará y enrutará los datos.
COPY vector.toml .

# Crea un directorio dentro del contenedor que será usado para montar los logs del host.
# Este es el directorio que la fuente 'file' en `vector.toml` monitoreará.
RUN mkdir -p /var/log/app

# Expone el puerto 8686. Aunque no es estrictamente necesario para esta configuración básica de archivo a consola,
# es un puerto común utilizado por Vector para fuentes o destinos basados en HTTP/TCP, y una buena práctica para futuras extensiones.
EXPOSE 8686

# Comando por defecto para iniciar Vector con el archivo de configuración especificado.
# Vector leerá esta configuración y comenzará a ejecutar sus pipelines de datos.
CMD ["vector", "--config", "/etc/vector/vector.toml"]

vector.toml

# vector.toml
# Configuración básica de Vector: Lee de un archivo local y envía a la consola.

# Define una fuente de tipo 'file' para monitorear y recolectar logs de una aplicación.
# Vector observará el archivo especificado para nuevas líneas.
[sources.my_app_logs]
  type = "file"
  # La ruta al archivo de log dentro del contenedor que Vector debe monitorear.
  # Asegúrate de que este directorio `/var/log/app` se mapee desde un directorio del host
  # (por ejemplo, `./logs`) usando el comando `podman run -v` o `docker run -v`.
  include = ["/var/log/app/dummy.log"]
  # Opcional: Ajusta el intervalo de sondeo para que Vector verifique el archivo.
  # Por defecto, es bastante eficiente, pero puedes ajustarlo si los logs no se escriben continuamente.
  # polling_interval_secs = 1

# Define un destino de tipo 'console' para imprimir los eventos procesados por Vector.
# Este destino enviará la salida directamente al stdout del contenedor.
[sinks.my_console_sink]
  type = "console"
  # Especifica qué fuentes deben ser procesadas por este sink. En este caso, `my_app_logs`.
  inputs = ["my_app_logs"]
  # Configura la codificación de la salida. JSON es un formato común y legible para logs estructurados.
  encoding.codec = "json"

logs/dummy.log

{"timestamp": "2023-10-27T10:00:00Z", "level": "INFO", "message": "User logged in"}
{"timestamp": "2023-10-27T10:00:05Z", "level": "DEBUG", "message": "Processing request 123"}
{"timestamp": "2023-10-27T10:00:10Z", "level": "ERROR", "message": "Failed to connect to database", "error_code": 500}
