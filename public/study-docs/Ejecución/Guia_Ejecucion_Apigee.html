Guia_Ejecucion_Apigee

Explicación

Apigee es una plataforma de gestión de API robusta. Dada su complejidad y naturaleza típicamente en la nube o en entornos empresariales, levantar una "instancia básica" completa de Apigee Edge o Apigee X localmente con Docker o Podman no es una tarea sencilla ni se proporciona un método oficial y ligero para ello. Sin embargo, el Apigee Edge Microgateway (Microgateway) es un componente ligero que permite implementar proxies de API localmente, aplicando políticas de Apigee y enrutando tráfico a backends. Esta guía te permitirá levantar una instancia local del Microgateway en modo standalone, lo que significa que no se conectará a una instancia de Apigee Edge/X completa, sino que cargará sus definiciones de proxy desde archivos locales. Es la forma más práctica de obtener una experiencia "Apigee" básica y local.

Esta configuración utilizará docker-compose para orquestar el Microgateway:

1. Dockerfile: Construye una imagen de Node.js, instala globalmente apigee-microgateway y copia los archivos de configuración y proxy.

2. docker-compose.yml: Define el servicio apigee-microgateway, construyendo la imagen desde el Dockerfile local, mapeando el puerto 8000 y montando los archivos de configuración.

3. config.yaml: Archivo de configuración principal del Microgateway. Define el puerto y una sección management básica, aunque no se use en modo standalone.

4. default.yaml: Define un proxy de API simple (/my-proxy) que enruta las solicitudes a https://httpbin.org/get. Esto te permitirá probar que el Microgateway está funcionando.

Pasos para ejecutar:

1. Guarda los archivos Dockerfile, docker-compose.yml, config.yaml y default.yaml en un mismo directorio.

2. Abre tu terminal en ese directorio.

3. Ejecuta el comando docker-compose up -d para construir la imagen y levantar el contenedor.

4. Una vez que el contenedor esté en ejecución (puedes verificar con docker-compose ps), puedes probar el proxy accediendo a http://localhost:8000/my-proxy en tu navegador o con curl.

Para detener y eliminar los contenedores, ejecuta docker-compose down.

Comandos de Ejecución

docker-compose up -d

Archivos de Configuración

Dockerfile

FROM node:18-alpine

WORKDIR /app

# Instala Apigee Edge Microgateway globalmente
RUN npm install -g apigee-microgateway

# Copia los archivos de configuración del Microgateway
COPY config.yaml .
COPY default.yaml .

# Expone el puerto por defecto del Apigee Microgateway
EXPOSE 8000

# Inicia Apigee Edge Microgateway en modo standalone
# '-c config.yaml' especifica el archivo de configuración del Microgateway.
# '--proxyDir /app' le dice al Microgateway que busque las definiciones de proxy
# (como default.yaml) en el directorio actual.
CMD ["sh", "-c", "edgemicro start -c config.yaml --proxyDir /app"]

docker-compose.yml

version: '3.8'
services:
  apigee-microgateway:
    build:
      context: .
      dockerfile: Dockerfile
    ports:
      - "8000:8000" # Mapea el puerto del host al puerto del contenedor
    volumes:
      # Monta los archivos de configuración para que el contenedor los pueda usar
      - ./config.yaml:/app/config.yaml
      - ./default.yaml:/app/default.yaml
    # El comando para iniciar el microgateway, tal como se especifica en el Dockerfile
    command: sh -c "edgemicro start -c config.yaml --proxyDir /app"
    restart: always # Asegura que el contenedor se reinicie si falla

config.yaml

# Archivo de configuración para Apigee Edge Microgateway en modo standalone
# Este archivo define los ajustes básicos para el Microgateway.

runtime:
  # Un ID de cluster para la instancia del Microgateway
  clusterId: apigee-microgateway-local
  # logLevel: info # Descomentar para cambiar el nivel de log

gateway:
  # El puerto en el que el Microgateway escuchará las solicitudes entrantes
  port: 8000
  # plugins:
  #   dir: /app/plugins # Directorio donde se pueden encontrar los plugins
  #   sequence:        # Secuencia de ejecución de plugins
  #     - cors

# Sección de gestión (management) - Requerida aunque no se use en modo standalone.
# La URL puede ser un marcador de posición, ya que no nos conectamos a una instancia de Apigee Edge.
management:
  url: http://localhost:8080/v1
  virtualHosts:
    - default # Nombre del host virtual predeterminado

default.yaml

# Definición de proxy para Apigee Edge Microgateway en modo standalone
# Este archivo define cómo el Microgateway manejará las solicitudes para una API específica.

proxy:
  # Nombre único para este proxy
  name: my-simple-proxy
  # La ruta base de la API que este proxy manejará. Las solicitudes a /my-proxy/* serán enrutadas.
  base_path: /my-proxy
  # Configuración del endpoint de destino (backend) para este proxy
  target_endpoint:
    name: default # Nombre del endpoint de destino
    url: https://httpbin.org/get # URL del servicio backend al que se enrutarán las solicitudes
