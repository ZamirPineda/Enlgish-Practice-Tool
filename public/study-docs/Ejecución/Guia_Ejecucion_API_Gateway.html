Guia_Ejecucion_API Gateway

Explicación

Este setup utiliza Docker Compose para levantar una instancia básica de Kong Gateway junto con una base de datos PostgreSQL.

Componentes:

  • kong-database: Un contenedor PostgreSQL que actúa como la base de datos de configuración de Kong. Los datos se persisten en un volumen llamado kong_data.
  • kong: El contenedor de Kong Gateway. Este servicio se construye a partir de un Dockerfile local que extiende la imagen oficial de Kong, demostrando cómo se podrían añadir personalizaciones (en este caso, curl). Kong se conecta a la base de datos kong-database y expone los siguientes puertos:
  • * 8000 (HTTP) y 8443 (HTTPS): Para el proxy de la API. Aquí es donde los clientes harán las solicitudes a tus APIs a través de Kong.
  • * 8001 (HTTP) y 8444 (HTTPS): Para la API de administración de Kong. Esta API se utiliza para configurar Kong (añadir servicios, rutas, plugins, etc.).

Pasos a seguir:

1. Crear los archivos: Guarda el contenido del Dockerfile como Dockerfile y el contenido del docker-compose.yml como docker-compose.yml en el mismo directorio.

2. Iniciar los servicios: Ejecuta el comando docker-compose up -d en la terminal desde el directorio donde guardaste los archivos. Esto construirá la imagen de Kong y levantará ambos contenedores en segundo plano.

3. Verificar el estado: Una vez que los contenedores estén en marcha, puedes verificar su estado con docker-compose ps.

4. Configurar Kong: Puedes interactuar con la API de administración de Kong en http://localhost:8001. Por ejemplo, para verificar que Kong está funcionando, puedes ejecutar curl -i http://localhost:8001.

5. Añadir un servicio y una ruta (ejemplo):

  • * Crear un servicio:
        curl -X POST http://localhost:8001/services \
            --data 'name=my-service' \
            --data 'url=http://httpbin.org'
  • * Añadir una ruta al servicio:
        curl -X POST http://localhost:8001/services/my-service/routes \
            --data 'paths[]=/test'
  • * Probar la API a través de Kong: Ahora puedes acceder a http://httpbin.org a través de Kong: 
        curl -i http://localhost:8000/test/get

Deberías ver la respuesta de httpbin.org.

6. Detener y limpiar: Cuando termines, puedes detener y eliminar los contenedores y los volúmenes (conservando los datos de la DB) con docker-compose down. Para eliminar también los datos persistentes, usa docker-compose down -v.

Comandos de Ejecución

docker-compose up -d

Archivos de Configuración

Dockerfile

FROM kong:latest

# Comentarios sobre el Dockerfile:
# Este Dockerfile extiende la imagen oficial de Kong.
# Para una configuración básica, la imagen oficial es a menudo suficiente.
# Sin embargo, este ejemplo demuestra cómo se podría personalizar.
# Aquí, simplemente instalamos 'curl' para propósitos de depuración o testing dentro del contenedor.
# En un escenario real, aquí se instalarían plugins personalizados, dependencias adicionales,
# o se copiarían configuraciones específicas.

USER root

# Instalar 'curl' (ejemplo de personalización)
RUN apt-get update && apt-get install -y --no-install-recommends \
    curl \
    && rm -rf /var/lib/apt/lists/*

# Restaurar el usuario a 'kong' para mantener los principios de menor privilegio
USER kong

docker-compose.yml

version: '3.8'

services:
  kong-database:
    image: postgres:13
    container_name: kong-database
    restart: on-failure
    environment:
      POSTGRES_USER: kong
      POSTGRES_DB: kong
      POSTGRES_PASSWORD: ${KONG_DB_PASSWORD:-kong} # Usa una variable de entorno o un valor por defecto
    volumes:
      - kong_data:/var/lib/postgresql/data # Persistencia de datos
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U kong"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - kong-net

  kong:
    build: .
    container_name: kong
    restart: on-failure
    environment:
      KONG_DATABASE: postgres
      KONG_PG_HOST: kong-database
      KONG_PG_USER: kong
      KONG_PG_PASSWORD: ${KONG_DB_PASSWORD:-kong}
      KONG_PG_DATABASE: kong
      KONG_PROXY_ACCESS_LOG: /dev/stdout
      KONG_ADMIN_ACCESS_LOG: /dev/stdout
      KONG_PROXY_ERROR_LOG: /dev/stderr
      KONG_ADMIN_ERROR_LOG: /dev/stderr
      KONG_ADMIN_LISTEN: 0.0.0.0:8001, 0.0.0.0:8444 ssl # Escuchar en todas las interfaces
      KONG_PROXY_LISTEN: 0.0.0.0:8000, 0.0.0.0:8443 ssl
    ports:
      - "8000:8000" # Proxy HTTP
      - "8443:8443" # Proxy HTTPS
      - "8001:8001" # Admin API HTTP
      - "8444:8444" # Admin API HTTPS
    depends_on:
      kong-database:
        condition: service_healthy # Esperar a que la DB esté saludable
    healthcheck:
      test: ["CMD", "kong", "health"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - kong-net

volumes:
  kong_data: # Define el volumen con nombre para los datos de PostgreSQL

networks:
  kong-net: # Define una red personalizada
