Guia_Ejecucion_Oracle

Explicación

Esta guía le permitirá levantar una instancia local de Oracle Database Express Edition (XE) usando gvenzl/oracle-xe, una imagen Docker muy popular y fácil de usar para entornos de desarrollo. Utilizaremos docker-compose para simplificar la configuración, la persistencia de datos y la gestión de la base de datos. Se expondrán los puertos 1521 para conexiones SQL y 8080 para acceder a la interfaz de APEX y SQL Developer Web.

Pasos a seguir:

1. Guarda los archivos: Crea un directorio para tu proyecto (ej. oracle-xe-local). Dentro de él, guarda el contenido proporcionado en los archivos docker-compose.yml, Dockerfile y healthcheck.sql con sus respectivos nombres.

2. Ajusta la contraseña: Abre docker-compose.yml y cambia your_secure_password por una contraseña segura y real. Esta será la contraseña para los usuarios SYS, SYSTEM y PDBADMIN.

3. Inicia el contenedor: Desde el directorio donde guardaste los archivos, ejecuta el comando docker-compose up -d.

4. Verifica el estado: Puedes verificar el estado de los contenedores con docker-compose ps y los logs con docker-compose logs -f oracle-xe. La base de datos puede tardar unos minutos en inicializarse completamente. La comprobación de salud (healthcheck) en docker-compose.yml ayudará a confirmar que está lista.

5. Conéctate a la base de datos: Una vez que el contenedor esté en funcionamiento, podrás conectarte a la base de datos utilizando un cliente SQL (como SQL Developer, DBeaver o sqlplus) a través del puerto 1521 en localhost.

  • * Host: localhost
  • * Puerto: 1521
  • * Service Name (PDB): XEPDB1 (por defecto)
  • * Usuario: system o sys (con el rol SYSDBA)
  • * Contraseña: La que definiste en ORACLE_PASSWORD.

6. Acceso Web: Accede a SQL Developer Web o APEX (si está configurado) a través de http://localhost:8080/ords/sql-developer o http://localhost:8080/ords/apex.

Este setup provee una base de datos Oracle XE funcional para desarrollo, con persistencia de datos y una forma sencilla de gestión.

Comandos de Ejecución

docker-compose up -d

Archivos de Configuración

Dockerfile

# Dockerfile para una instancia básica de Oracle XE
# Utiliza la imagen gvenzl/oracle-xe como base, que ya está preconfigurada para Oracle XE.
# Esto permite una puesta en marcha rápida sin necesidad de un Dockerfile complejo.
FROM gvenzl/oracle-xe:21-slim-faststart

# Opcional: Define metadatos para tu imagen personalizada.
LABEL maintainer="Tu Nombre <tu.email@example.com>"
LABEL description="Imagen personalizada de Oracle XE para desarrollo local"

# Puedes añadir aquí cualquier script de inicialización o configuración adicional
# que desees ejecutar cuando el contenedor se inicie por primera vez.
# Por ejemplo, para crear esquemas específicos, usuarios o cargar datos iniciales.
# Si necesitas scripts, colócalos en el directorio ./init_scripts y descomenta la línea
# de volumen en docker-compose.yml que los mapea a /container-entrypoint-initdb.d/
# COPY ./init_scripts/my_init_script.sql /container-entrypoint-initdb.d/

# La imagen base ya expone los puertos necesarios (1521 para SQL, 8080 para APEX/SQL Developer Web).
# No es necesario re-exponerlos aquí a menos que quieras cambiarlos o añadir otros.
EXPOSE 1521
EXPOSE 8080

# El ENTRYPOINT y CMD ya están definidos en la imagen base para iniciar la base de datos.
# No es necesario modificarlos para un setup básico.

docker-compose.yml

version: '3.8'

services:
  oracle-xe:
    image: gvenzl/oracle-xe:21-slim-faststart
    container_name: oracle-xe
    hostname: oracle-xe
    ports:
      - "1521:1521" # Puerto para conexiones SQL
      - "8080:8080" # Puerto para APEX y SQL Developer Web
    environment:
      # Establece la contraseña para los usuarios SYS, SYSTEM y PDBADMIN.
      # ¡CAMBIA ESTO POR UNA CONTRASEÑA SEGURA Y REAL!
      ORACLE_PASSWORD: "your_secure_password"
      # Opcional: Nombre del PDB (Plugable Database). Por defecto es XEPDB1.
      # ORACLE_PDB: "MYPDB"
      # Opcional: Permite conexiones remotas (por defecto true, pero explícito es bueno).
      ORACLE_ALLOW_REMOTE: "true"
    volumes:
      - oracle_xe_data:/opt/oracle/oradata # Para persistir los datos de la base de datos
      # Opcional: Para scripts de inicialización que se ejecuten al primer arranque.
      # Descomenta la siguiente línea y crea un directorio 'init_scripts' con tus .sql o .sh
      # - ./init_scripts:/container-entrypoint-initdb.d/
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "sqlplus", "-L", "system/$ORACLE_PASSWORD@//localhost:1521/XEPDB1", "AS SYSDBA", "-S", "@/healthcheck.sql"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 120s # Dar tiempo a la BD para iniciar
      # En lugar de usar @healthcheck.sql directamente, podríamos copiarlo y ejecutarlo desde dentro del contenedor
      # Si el healthcheck falla, intenta conectarte con sqlplus desde el host para diagnosticar.

volumes:
  oracle_xe_data:
    driver: local

healthcheck.sql

WHENEVER SQLERROR EXIT 1;
SELECT 1 FROM DUAL;
EXIT;
