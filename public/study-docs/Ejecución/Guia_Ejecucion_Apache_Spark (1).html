Guia_Ejecucion_Apache Spark

Explicación

Esta guía te permite levantar una instancia básica de Apache Spark en modo distribuido (master y worker) utilizando docker-compose. Se basa en las imágenes oficiales de Bitnami Spark, que facilitan la configuración mediante variables de entorno.

Estructura del Proyecto:

Crea los siguientes archivos en una carpeta vacía:

  • Dockerfile.master: Define la imagen para el nodo master de Spark.
  • Dockerfile.worker: Define la imagen para el nodo worker de Spark.
  • docker-compose.yml: Orquesta los servicios del master y worker, define sus configuraciones y la red compartida.

Pasos:

1. Crear los archivos: Guarda el contenido proporcionado para Dockerfile.master, Dockerfile.worker y docker-compose.yml en sus respectivos archivos dentro del mismo directorio.

2. Iniciar los contenedores: Ejecuta el comando docker-compose up -d. Esto construirá las imágenes y levantará los servicios en segundo plano.

3. Verificar el estado: Una vez levantados, puedes acceder a la interfaz de usuario de Spark Master en http://localhost:8080. Allí podrás ver el estado del master y los workers conectados.

4. Ejecutar una aplicación Spark: Para interactuar con tu clúster Spark, puedes acceder al contenedor del master y ejecutar spark-shell o pyspark:

docker exec -it spark-master spark-shell
# O para Python
docker exec -it spark-master pyspark

Dentro del spark-shell o pyspark, puedes ejecutar código Spark. Por ejemplo:

val data = 1 to 1000
val distData = sc.parallelize(data)
distData.count()

5. Detener y limpiar: Cuando hayas terminado, puedes detener y eliminar los contenedores con:

docker-compose down

Esta configuración te proporciona un entorno Spark funcional para desarrollo y pruebas locales.

Comandos de Ejecución

docker-compose up -d

Archivos de Configuración

Dockerfile.master

# Dockerfile para Spark Master
# Utiliza la imagen oficial de Bitnami Spark, que ya viene configurada para fácil despliegue.
FROM bitnami/spark:3.5.0
# La imagen de Bitnami ya configura los puertos y el punto de entrada
# basándose en variables de entorno, que se definirán en docker-compose.yml.
# No necesitamos configurar CMD o EXPOSE aquí explícitamente si usamos las variables.

Dockerfile.worker

# Dockerfile para Spark Worker
# Utiliza la misma imagen base que el master.
FROM bitnami/spark:3.5.0
# Al igual que el master, la configuración del worker se manejará con variables de entorno
# en docker-compose.yml.

docker-compose.yml

version: '3.8'

services:
  spark-master:
    build:
      context: .
      dockerfile: Dockerfile.master
    container_name: spark-master
    hostname: spark-master
    ports:
      - "8080:8080" # Spark Master UI
      - "7077:7077" # Spark Master internal communication
    environment:
      # Configuración para el rol de Master
      - SPARK_MODE=master
      # Variables para deshabilitar la autenticación/encriptación para un setup local simple
      - SPARK_RPC_AUTHENTICATION_ENABLED=no
      - SPARK_RPC_ENCRYPTION_ENABLED=no
      - SPARK_LOCAL_STORAGE_ENCRYPTION_ENABLED=no
    networks:
      - spark-net

  spark-worker:
    build:
      context: .
      dockerfile: Dockerfile.worker
    container_name: spark-worker
    hostname: spark-worker
    ports:
      - "8081:8081" # Spark Worker UI (puede ser dinámico, pero lo fijamos para este ejemplo)
    environment:
      # Configuración para el rol de Worker
      - SPARK_MODE=worker
      # URL del master para que el worker se conecte
      - SPARK_MASTER_URL=spark://spark-master:7077
      # Recursos asignados al worker
      - SPARK_WORKER_CORES=1
      - SPARK_WORKER_MEMORY=1G
      # Variables para deshabilitar la autenticación/encriptación para un setup local simple
      - SPARK_RPC_AUTHENTICATION_ENABLED=no
      - SPARK_RPC_ENCRYPTION_ENABLED=no
      - SPARK_LOCAL_STORAGE_ENCRYPTION_ENABLED=no
    depends_on:
      - spark-master
    networks:
      - spark-net

networks:
  spark-net:
    driver: bridge
