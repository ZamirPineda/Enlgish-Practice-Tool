Guia_Ejecucion_Redis

Explicación

Esta guía te permitirá levantar una instancia básica de Redis localmente usando Podman o Docker. Incluye un Dockerfile sencillo para construir la imagen y un archivo de configuración básico redis.conf para personalizar la instancia, junto con los comandos necesarios para construir y ejecutar el contenedor. Redis es un almacén de datos en memoria de código abierto, utilizado como base de datos, caché y bróker de mensajes.

Comandos de Ejecución

podman build -t my-redis . && podman run -d -p 6379:6379 --name my-redis -v $(pwd)/redis.conf:/usr/local/etc/redis/redis.conf my-redis redis-server /usr/local/etc/redis/redis.conf

Archivos de Configuración

Dockerfile

# Utiliza la imagen oficial de Redis como base.
# Esto asegura que tenemos una instalación estable y bien mantenida de Redis.
FROM redis:latest

# El puerto 6379 es el puerto por defecto de Redis.
# EXPOSE es solo una documentación, el mapeo de puertos real se hace al ejecutar el contenedor.
EXPOSE 6379

# CMD ya está definido en la imagen base de Redis para ejecutar 'redis-server'.
# No necesitamos sobrescribirlo a menos que queramos pasar argumentos por defecto.
# En este caso, pasaremos la configuración personalizada al ejecutar el contenedor.

redis.conf

# Archivo de configuración básico para Redis.
# Puedes personalizar este archivo según tus necesidades.

# Puerto en el que Redis escuchará las conexiones.
port 6379

# No ejecutar como daemon. Esto es ideal para contenedores, ya que el proceso principal debe estar en primer plano.
daemonize no

# Activar la persistencia AOF (Append Only File).
# AOF registra cada operación de escritura que el servidor recibe.
appendonly yes

# Especifica la política de persistencia RDB (Redis Database).
# Guarda el conjunto de datos en el disco cada 900 segundos (15 minutos) si al menos 1 clave ha cambiado.
save 900 1
# Guarda el conjunto de datos en el disco cada 300 segundos (5 minutos) si al menos 10 claves han cambiado.
save 300 10
# Guarda el conjunto de datos en el disco cada 60 segundos si al menos 10000 claves han cambiado.
save 60 10000

# Establece un límite máximo de memoria para Redis.
# Si se alcanza este límite, Redis intentará liberar memoria según la política de 'maxmemory-policy'.
maxmemory 256mb

# Política de desalojo de claves cuando se alcanza 'maxmemory'.
# 'noeviction': Devuelve errores en las operaciones de escritura cuando la memoria está llena.
maxmemory-policy noeviction

# Configura el nivel de verbosidad del log de Redis. Puede ser debug, verbose, notice, warning.
loglevel notice
