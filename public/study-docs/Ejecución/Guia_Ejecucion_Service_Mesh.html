Guia_Ejecucion_Service Mesh

Explicación

Esta configuración proporciona una demostración básica de los conceptos de un Service Mesh utilizando Envoy Proxy como un sidecar virtual para dos servicios simples de Python (Service A y Service B). Aunque no es una implementación completa de un Service Mesh como Istio o Linkerd (que suelen requerir Kubernetes), ilustra cómo un proxy puede interceptar, enrutar y equilibrar la carga del tráfico entre servicios.

Componentes:

  • Service A y Service B: Son aplicaciones Flask muy simples que devuelven un mensaje "Hello from Service X!". Representan microservicios de tu aplicación.
  • Envoy Proxy: Actúa como un proxy de "Service Mesh". Está configurado para escuchar en el puerto 8000 y distribuir las peticiones entrantes entre Service A y Service B utilizando una política de round-robin. También expone su interfaz de administración en el puerto 9901.
  • docker-compose.yml: Orquesta la construcción y ejecución de los tres contenedores, asegurando que Envoy enrute el tráfico correctamente entre los servicios en la red definida.

Pasos para ejecutar:

1. Guarda los archivos con las rutas de directorio especificadas (ej. crea una carpeta service_a y dentro de ella Dockerfile, app.py, requirements.txt).

2. Navega a la raíz del directorio donde guardaste docker-compose.yml.

3. Ejecuta el comando docker-compose up -d.

4. Una vez que los contenedores estén levantados y saludables, puedes acceder al Service Mesh a través de http://localhost:8000. Cada vez que actualices la página, verás alternativamente mensajes de "Hello from Service A!" y "Hello from Service B!" debido al balanceo de carga de Envoy.

5. Para detener y eliminar los contenedores, usa docker-compose down.

Archivos de Configuración

service_a/Dockerfile

FROM python:3.9-slim-buster
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY app.py .
EXPOSE 5000
CMD ["python", "app.py"]

docker-compose.yml

version: '3.8'
services:
  service-a:
    build: ./service_a
    container_name: service-a
    expose:
      - "5000"
    networks:
      - servicemesh_net
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:5000"]
      interval: 5s
      timeout: 3s
      retries: 5

  service-b:
    build: ./service_b
    container_name: service-b
    expose:
      - "5000"
    networks:
      - servicemesh_net
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:5000"]
      interval: 5s
      timeout: 3s
      retries: 5

  envoy:
    image: envoyproxy/envoy:v1.28.0
    container_name: envoy
    volumes:
      - ./envoy.yaml:/etc/envoy/envoy.yaml
    ports:
      - "8000:8000" # Puerto para peticiones entrantes
      - "9901:9901" # Puerto de administración de Envoy
    command: "envoy -c /etc/envoy/envoy.yaml --service-cluster front-proxy"
    depends_on:
      service-a:
        condition: service_healthy
      service-b:
        condition: service_healthy
    networks:
      - servicemesh_net

networks:
  servicemesh_net:
    driver: bridge

envoy.yaml

admin:
  access_log_path: /dev/stdout
  address:
    socket_address:
      protocol: TCP
      address: 0.0.0.0
      port_value: 9901

static_resources:
  listeners:
  - name: listener_0
    address:
      socket_address:
        protocol: TCP
        address: 0.0.0.0
        port_value: 8000
    filter_chains:
    - filters:
      - name: envoy.filters.network.http_connection_manager
        typed_config:
          "@type": type.googleapis.com/envoy.extensions.filters.network.http_connection_manager.v3.HttpConnectionManager
          stat_prefix: ingress_http
          codec_type: AUTO
          route_config:
            name: local_route
            virtual_hosts:
            - name: backend
              domains: ["*"]
              routes:
              - match:
                  prefix: "/"
                route:
                  cluster: services_cluster
          http_filters:
          - name: envoy.filters.http.router
            typed_config:
              "@type": type.googleapis.com/envoy.extensions.filters.http.router.v3.Router

  clusters:
  - name: services_cluster
    connect_timeout: 0.25s
    type: LOGICAL_DNS
    lb_policy: ROUND_ROBIN
    load_assignment:
      cluster_name: services_cluster
      endpoints:
      - lb_endpoints:
        - endpoint:
            address:
              socket_address:
                address: service-a # Nombre del servicio en la red Docker
                port_value: 5000
      - lb_endpoints:
        - endpoint:
            address:
              socket_address:
                address: service-b # Nombre del servicio en la red Docker
                port_value: 5000

service_a/app.py

from flask import Flask

app = Flask(__name__)

@app.route('/')
def hello_a():
    return "Hello from Service A!"

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000)
