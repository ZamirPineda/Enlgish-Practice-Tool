Guia_Ejecucion_HBase

Explicación

Esta guía proporciona una configuración básica para ejecutar Apache HBase localmente utilizando docker-compose (compatible con Docker y Podman). HBase es una base de datos distribuida, no relacional (NoSQL), que se ejecuta sobre HDFS (en este caso, en modo standalone dentro del contenedor) y utiliza Apache ZooKeeper para la coordinación. La configuración incluye los siguientes componentes:

1. ZooKeeper: Un servicio de coordinación distribuida esencial para HBase.

2. HBase Master/RegionServer: Un único contenedor que actúa como HBase Master y RegionServer, configurado para usar el servicio de ZooKeeper local.

Pasos para ejecutar:

1. Guarda los archivos: Crea un directorio, por ejemplo, hbase-setup, y guarda los archivos docker-compose.yml y Dockerfile (aunque el Dockerfile es opcional para este setup, se incluye para cumplir el esquema y mostrar una base de personalización) en él.

2. Inicia los contenedores: Abre una terminal en el directorio hbase-setup y ejecuta el comando: 

    docker-compose up -d

Esto iniciará el contenedor de ZooKeeper y, una vez que esté saludable, el contenedor de HBase.

3. Verifica el estado: Una vez que los contenedores estén en ejecución, puedes acceder a la UI del HBase Master en tu navegador:

  • * HBase Master UI: http://localhost:16010

4. Accede al shell de HBase (opcional):

    docker exec -it hbase-master hbase shell

Desde el shell, puedes interactuar con HBase, por ejemplo, listar tablas con list.

5. Detener los contenedores:

    docker-compose down

Notas:

  • Se ha optado por la imagen harisekhon/hbase para simplificar la configuración, ya que es una imagen robusta que empaqueta HBase de forma eficiente.
  • El Dockerfile provisto es un ejemplo de cómo podrías extender la imagen base para añadir personalizaciones, aunque para esta guía no es estrictamente necesario construirlo.

Archivos de Configuración

Dockerfile

# Dockerfile para una imagen de HBase personalizada (opcional)
# Este Dockerfile es un ejemplo de cómo podrías construir tu propia imagen de HBase
# si necesitaras personalizaciones que no están en una imagen preconstruida.
# Para esta guía práctica, el docker-compose.yml utiliza directamente la imagen
# 'harisekhon/hbase' para simplificar el proceso.

FROM harisekhon/hbase:latest

# Este Dockerfile simplemente extiende la imagen base de Harisekhon.
# Aquí podrías añadir tus propias configuraciones, scripts, plugins, o herramientas
# que necesites dentro del contenedor de HBase.

# Ejemplo: Añadir un script de inicio personalizado (si fuera necesario)
# COPY custom-init.sh /usr/local/bin/
# RUN chmod +x /usr/local/bin/custom-init.sh
# ENTRYPOINT ["/usr/local/bin/custom-init.sh"]

# Para esta configuración básica, no se requieren modificaciones adicionales.
# La imagen 'harisekhon/hbase' ya viene con todo lo necesario.

docker-compose.yml

version: '3.8'

services:
  zookeeper:
    image: zookeeper:3.8.0
    container_name: zookeeper
    hostname: zookeeper
    restart: unless-stopped
    ports:
      - "2181:2181"
    environment:
      ZOO_MY_ID: 1
      ZOO_SERVERS: server.1=0.0.0.0:2888:3888
    healthcheck:
      test: ["CMD-SHELL", "echo srvr | nc -w 2 localhost 2181"]
      interval: 10s
      timeout: 5s
      retries: 5

  hbase-master:
    image: harisekhon/hbase:latest
    container_name: hbase-master
    hostname: hbase-master
    restart: unless-stopped
    ports:
      - "16010:16010" # UI del HBase Master
      - "16000:16000" # Puerto RPC del HBase Master
      - "16020:16020" # Puerto RPC del RegionServer
      - "16030:16030" # UI del RegionServer
    environment:
      HBASE_ZOOKEEPER_QUORUM: zookeeper:2181
      # Las variables de entorno para puertos son generalmente manejadas por la imagen
      # Pero se pueden especificar si fuera necesario para override o claridad
      # HBASE_MASTER_PORT: 16000
      # HBASE_MASTER_WEBUI_PORT: 16010
      # HBASE_REGIONSERVER_PORT: 16020
      # HBASE_REGIONSERVER_WEBUI_PORT: 16030
    depends_on:
      zookeeper:
        condition: service_healthy
    volumes:
      - hbase_data:/opt/hbase/data
    healthcheck:
      test: ["CMD-SHELL", "curl -f http://localhost:16010 || exit 1"]
      interval: 30s
      timeout: 10s
      retries: 5

volumes:
  hbase_data:
