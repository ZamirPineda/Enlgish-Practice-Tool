Guia_Ejecucion_CockroachDB

Explicación

Esta guía te permitirá levantar un cluster básico de 3 nodos de CockroachDB localmente utilizando docker-compose (o podman-compose). CockroachDB es una base de datos SQL distribuida, elástica y tolerante a fallos, diseñada para la nube. Esta configuración simula un cluster distribuido, lo cual es fundamental para entender sus capacidades.

Componentes de la Configuración:

1. Dockerfile: Un archivo simple que utiliza la imagen oficial de CockroachDB. Esto permite construir una imagen personalizada si necesitaras añadir herramientas o configuraciones adicionales, aunque para este setup básico la imagen oficial es suficiente.

2. docker-compose.yml: Este archivo define un cluster de CockroachDB compuesto por tres nodos (roach1, roach2, roach3) y un servicio de inicialización (init).

  • * Cada nodo de CockroachDB se ejecuta en un contenedor separado, configurado para unirse a los otros nodos y formar el cluster.
  • * Se utilizan volúmenes persistentes (roachX_data) para asegurar que los datos no se pierdan al detener y reiniciar los contenedores.
  • * roach1 expone los puertos 26257 (SQL) y 8080 (UI de administración) al host para que puedas interactuar con el cluster.
  • * El servicio init se encarga de ejecutar el comando cockroach init una vez que todos los nodos están saludables, lo cual es necesario para que el cluster funcione.

Pasos a Seguir:

1. Guarda los archivos: Crea un directorio cockroachdb-cluster y guarda el Dockerfile y el docker-compose.yml dentro de él.

2. Levanta el cluster: Abre tu terminal en el directorio cockroachdb-cluster y ejecuta el comando de runCommands.

3. Verifica el estado: Una vez que los contenedores estén en ejecución, puedes verificar su estado con docker-compose ps. También puedes ver los logs con docker-compose logs -f.

4. Accede a la UI de administración: Abre tu navegador web y visita http://localhost:8080. Aquí podrás ver el estado del cluster, las métricas y la topología.

5. Conéctate vía SQL: Puedes conectar un cliente SQL (como psql o el mismo CLI de CockroachDB) al puerto 26257 del host. Por ejemplo, desde otro contenedor o instalando el CLI localmente:

    docker run -it --rm --network host cockroachdb/cockroach sql --insecure --host=localhost:26257
    # O si tienes el CLI instalado localmente:
    cockroach sql --insecure --host=localhost:26257

6. Limpia el cluster: Para detener y eliminar todos los contenedores y los volúmenes de datos (eliminando los datos persistentes), ejecuta docker-compose down -v.

Nota Importante: La configuración utiliza la bandera --insecure para simplificar el setup local. Esto significa que las comunicaciones no están cifradas y no hay autenticación. NUNCA utilices --insecure en un entorno de producción.

Comandos de Ejecución

docker-compose up -d

Archivos de Configuración

Dockerfile

# Dockerfile para una instancia de CockroachDB
# Este Dockerfile utiliza la imagen oficial de CockroachDB.
# Puedes personalizarlo si necesitas agregar herramientas o configuraciones específicas.

# Usa la imagen oficial de CockroachDB.
# Se recomienda especificar una versión para producción, por ejemplo, cockroachdb/cockroach:v23.2.3
FROM cockroachdb/cockroach:latest

# El ENTRYPOINT y CMD ya están definidos en la imagen base de CockroachDB,
# por lo que no es necesario redefinirlos a menos que se quiera cambiar el comportamiento por defecto.
# La imagen base está optimizada para ejecutar 'cockroach start' o 'cockroach init'.

# Exponer los puertos por defecto de CockroachDB:
# 26257 para el cliente SQL
# 8080 para la UI de administración
EXPOSE 26257 8080

# Este Dockerfile es mínimo ya que la imagen oficial es bastante completa.
# Para un desarrollo local, puedes usar directamente la imagen oficial
# o esta imagen construida a partir de ella.

docker-compose.yml

version: '3.8'

services:
  roach1:
    build: .
    hostname: roach1
    container_name: roach1
    ports:
      - "26257:26257" # Puerto SQL
      - "8080:8080"   # Puerto de la UI de administración
    volumes:
      - roach1_data:/cockroach/cockroach-data
    command:
      # Inicia el nodo de CockroachDB.
      # --insecure: Para desarrollo local, no requiere certificados. NO USAR EN PRODUCCIÓN.
      # --store=/cockroach/cockroach-data: Directorio donde se almacenarán los datos.
      # --listen-addr=0.0.0.0:26257: Escucha conexiones SQL en todas las interfaces.
      # --http-addr=0.0.0.0:8080: Escucha la UI de administración.
      # --join: Nodos a los que intentar unirse para formar el cluster.
      # --advertise-addr: Dirección que otros nodos usarán para conectar a este nodo.
      # --cache: Porcentaje de memoria total del contenedor para la caché de CockroachDB.
      # --max-sql-memory: Porcentaje de memoria total para operaciones SQL.
      "start --insecure --store=/cockroach/cockroach-data --listen-addr=0.0.0.0:26257 --http-addr=0.0.0.0:8080 --join=roach1:26257,roach2:26257,roach3:26257 --cache=25% --max-sql-memory=25% --advertise-addr=roach1:26257"
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8080/health"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 10s

  roach2:
    build: .
    hostname: roach2
    container_name: roach2
    volumes:
      - roach2_data:/cockroach/cockroach-data
    command:
      "start --insecure --store=/cockroach/cockroach-data --listen-addr=0.0.0.0:26257 --http-addr=0.0.0.0:8080 --join=roach1:26257,roach2:26257,roach3:26257 --cache=25% --max-sql-memory=25% --advertise-addr=roach2:26257"
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8080/health"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 10s

  roach3:
    build: .
    hostname: roach3
    container_name: roach3
    volumes:
      - roach3_data:/cockroach/cockroach-data
    command:
      "start --insecure --store=/cockroach/cockroach-data --listen-addr=0.0.0.0:26257 --http-addr=0.0.0.0:8080 --join=roach1:26257,roach2:26257,roach3:26257 --cache=25% --max-sql-memory=25% --advertise-addr=roach3:26257"
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8080/health"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 10s

  init:
    build: .
    command: "init --insecure --host=roach1:26257"
    depends_on:
      roach1:
        condition: service_healthy
      roach2:
        condition: service_healthy
      roach3:
        condition: service_healthy
    # El contenedor de inicialización se ejecuta y sale.
    # Es crucial que todos los nodos estén listos y saludables antes de la inicialización.

volumes:
  roach1_data:
  roach2_data:
  roach3_data:
