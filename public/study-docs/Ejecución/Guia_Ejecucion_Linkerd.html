Guia_Ejecucion_Linkerd

Explicación

Linkerd es un service mesh ultraligero y de alto rendimiento para Kubernetes. Su función principal es añadir observabilidad, fiabilidad y seguridad a las aplicaciones de forma transparente, sin necesidad de modificar el código de la aplicación. Para funcionar, Linkerd requiere un clúster de Kubernetes.

Esta guía te permitirá "levantar" una instancia básica de Linkerd localmente utilizando Kind (Kubernetes in Docker/Podman) y el CLI de Linkerd dentro de un contenedor. Los pasos incluyen:

1. Crear un clúster de Kubernetes local con Kind: Kind es una herramienta que ejecuta clústeres de Kubernetes utilizando contenedores Docker/Podman como nodos.

2. Construir un contenedor con el CLI de Linkerd y kubectl: Este contenedor se utilizará para interactuar con el clúster de Kind.

3. Instalar el plano de control de Linkerd: El CLI de Linkerd desplegará los componentes necesarios (controlador, inyector de proxy, etc.) en el clúster de Kind.

4. Desplegar una aplicación de ejemplo e inyectar el proxy de Linkerd: Se desplegará una simple aplicación Nginx y se modificará para que Linkerd inyecte su sidecar proxy en los pods de la aplicación, habilitando así las funcionalidades del mesh.

Prerrequisitos:

  • Tener docker o podman instalado y funcionando.
  • Tener el CLI de kind instalado (puedes descargarlo desde https://kind.sigs.k8s.io/docs/user/quick-start/#installation).

El script setup.sh automatiza todos estos pasos.

Comandos de Ejecución

sh ./setup.sh

Archivos de Configuración

Dockerfile.linkerd-cli

FROM curlimages/curl:latest as downloader

ARG LINKERD_VERSION="stable-2.14.7" # Versión estable de Linkerd CLI
RUN curl -sLO "https://github.com/linkerd/linkerd2/releases/download/${LINKERD_VERSION}/linkerd2-cli-${LINKERD_VERSION}-linux-amd64" \
    && mv linkerd2-cli-${LINKERD_VERSION}-linux-amd64 /usr/local/bin/linkerd \
    && chmod +x /usr/local/bin/linkerd

ARG KUBECTL_VERSION="v1.28.0" # Versión de kubectl compatible con K8s (Kind)
RUN curl -LO "https://dl.k8s.io/release/${KUBECTL_VERSION}/bin/linux/amd64/kubectl" \
    && mv kubectl /usr/local/bin/kubectl \
    && chmod +x /usr/local/bin/kubectl

FROM alpine/git:latest # Utiliza una imagen base con bash y herramientas comunes
LABEL maintainer="YourName <your.email@example.com>"

# Instala bash si no está presente (alpine/git generalmente lo incluye)
RUN apk add --no-cache bash

# Copia los CLIs descargados de la etapa 'downloader'
COPY --from=downloader /usr/local/bin/linkerd /usr/local/bin/linkerd
COPY --from=downloader /usr/local/bin/kubectl /usr/local/bin/kubectl

WORKDIR /app

# Asegura herramientas de red como 'dig' para 'linkerd check'
RUN apk add --no-cache bind-tools # Proporciona dig, nslookup

CMD ["bash"]

sample-app.yaml

apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
  labels:
    app: nginx
spec:
  replicas: 1
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.14.2
        ports:
        - containerPort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: nginx-service
spec:
  selector:
    app: nginx
  ports:
    - protocol: TCP
      port: 80
      targetPort: 80
  type: ClusterIP

setup.sh

#!/bin/bash
set -euo pipefail

# --- Configuración --- #
KIND_CLUSTER_NAME="linkerd-local"

# --- Comprobación de prerrequisitos --- #
if ! command -v kind &> /dev/null; then
    echo "Error: El CLI de 'kind' no se encontró. Por favor, instálalo: https://kind.sigs.k8s.io/docs/user/quick-start/#installation"
    exit 1
fi

CONTAINER_CLI="docker"
if command -v podman &> /dev/null; then
    CONTAINER_CLI="podman"
    echo "Usando Podman para la gestión de contenedores."
elif command -v docker &> /dev/null; then
    echo "Usando Docker para la gestión de contenedores."
else
    echo "Error: No se encontró Docker ni Podman. Por favor, instala uno de ellos."
    exit 1
fi

# --- 1. Crear clúster de Kind --- #
echo "\n--- 1. Creando clúster de Kind '$KIND_CLUSTER_NAME' ... ---"
if ! kind get clusters | grep -q "^$KIND_CLUSTER_NAME$"; then
    kind create cluster --name "$KIND_CLUSTER_NAME" --config kind-config.yaml
    echo "Clúster '$KIND_CLUSTER_NAME' creado exitosamente."
else
    echo "El clúster Kind '$KIND_CLUSTER_NAME' ya existe. Saltando la creación."
fi

# Asegura que kubectl use el contexto del clúster Kind
kubectl config use "kind-$KIND_CLUSTER_NAME"

# --- 2. Construir imagen Docker del CLI de Linkerd --- #
echo "\n--- 2. Construyendo la imagen '$CONTAINER_CLI build -t linkerd-cli' ... ---"
$CONTAINER_CLI build -t linkerd-cli -f Dockerfile.linkerd-cli .
echo "Imagen 'linkerd-cli' construida exitosamente."

# --- 3. Instalar Linkerd y desplegar app de ejemplo --- #
echo "\n--- 3. Instalando Linkerd y desplegando aplicación de ejemplo... ---"

# Obtener el kubeconfig del clúster Kind y guardarlo temporalmente
KIND_KUBECONFIG_CONTENT=$(kind get kubeconfig --name "$KIND_CLUSTER_NAME")
echo "$KIND_KUBECONFIG_CONTENT" > /tmp/kind-kubeconfig.yml
chmod 600 /tmp/kind-kubeconfig.yml # Asegurar permisos adecuados

# Ejecutar el contenedor del CLI de Linkerd para interactuar con el clúster
$CONTAINER_CLI run --rm \
    -v /tmp/kind-kubeconfig.yml:/app/kubeconfig.yml \
    -v "$(pwd)":/app/project \
    -e KUBECONFIG=/app/kubeconfig.yml \
    linkerd-cli bash -c " \
        echo '  - Ejecutando 'linkerd check --pre'...'; \
        linkerd check --pre; \
        echo '  - Instalando plano de control de Linkerd...'; \
        linkerd install | kubectl apply -f -; \
        echo '  - Esperando a que el plano de control de Linkerd esté listo...'; \
        linkerd check --wait; \
        echo '  - Desplegando aplicación de ejemplo (nginx)...'; \
        kubectl apply -f /app/project/sample-app.yaml; \
        echo '  - Inyectando proxy de Linkerd en la aplicación de ejemplo...'; \
        linkerd inject /app/project/sample-app.yaml | kubectl apply -f -; \
        echo '  - Esperando a que la aplicación de ejemplo esté lista e inyectada...'; \
        kubectl rollout status deployment/nginx-deployment -n default --timeout=300s; \
        echo '  - Comprobación final de Linkerd...'; \
        linkerd check; \
    "

# Limpiar archivo kubeconfig temporal
rm /tmp/kind-kubeconfig.yml

echo "\n--- Instalación de Linkerd y la aplicación de ejemplo completada exitosamente. ---"

# --- Pasos Siguientes --- #
echo "\n--- Pasos Siguientes ---"
echo "Puedes explorar el dashboard de Linkerd ejecutando:"
echo "  $CONTAINER_CLI run --rm -v /tmp/kind-kubeconfig.yml:/app/kubeconfig.yml -e KUBECONFIG=/app/kubeconfig.yml linkerd-cli linkerd dashboard"
echo "O, si tienes el CLI de Linkerd instalado en tu host: 'linkerd dashboard'"
echo "Para limpiar el clúster de Kind, ejecuta: 'kind delete cluster --name $KIND_CLUSTER_NAME'"
