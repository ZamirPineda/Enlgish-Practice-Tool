Guia_Ejecucion_OpenTelemetry

Explicación

Esta guía te permitirá levantar una instancia básica de OpenTelemetry junto con herramientas de monitoreo como Jaeger, Prometheus y Grafana, utilizando Docker Compose. La configuración incluye un OpenTelemetry Collector que actúa como intermediario para recibir telemetría (rastros, métricas y logs) de tus aplicaciones y exportarla a los sistemas de backend.

Componentes:

  • OpenTelemetry Collector: Recibe datos OTLP (OpenTelemetry Protocol) de las aplicaciones, los procesa y los exporta. En esta configuración, reenvía rastros a Jaeger y expone métricas para que Prometheus las recoja.
  • Jaeger: Un sistema distribuido de rastreo que permite monitorear y solucionar problemas de transacciones complejas en entornos de microservicios. Recibe los rastros del Collector.
  • Prometheus: Un sistema de monitoreo y alerta basado en series temporales. Recoge las métricas expuestas por el Collector.
  • Grafana: Una plataforma de análisis y visualización. Se conectará a Jaeger (para rastros) y Prometheus (para métricas) para ofrecer paneles de control y exploraciones interactivas.

Pasos a seguir:

1. Guarda los contenidos proporcionados en los archivos docker-compose.yml, collector-config.yaml y prometheus.yml en un mismo directorio.

2. Abre una terminal en ese directorio.

3. Ejecuta el comando docker-compose up -d para levantar todos los contenedores.

4. Una vez que los contenedores estén en ejecución, podrás acceder a las interfaces web:

  • * Jaeger UI: http://localhost:16686
  • * Prometheus UI: http://localhost:9090
  • * Grafana UI: http://localhost:3000 (Usuario: admin, Contraseña: admin)

5. En Grafana, deberás añadir Prometheus y Jaeger como fuentes de datos:

  • * Para Prometheus: Configura una fuente de datos de tipo Prometheus apuntando a http://prometheus:9090.
  • * Para Jaeger: Configura una fuente de datos de tipo Jaeger apuntando a http://jaeger:14250 (o http://jaeger:14268 para HTTP, pero gRPC es preferido por el collector).

6. Ahora tus aplicaciones pueden enviar datos OTLP al Collector en http://localhost:4318 (HTTP) o grpc://localhost:4317 (gRPC).

Comandos de Ejecución

docker-compose up -d

Archivos de Configuración

docker-compose.yml

version: '3.8'
services:
  otel-collector:
    image: otel/opentelemetry-collector-contrib:latest
    container_name: otel-collector
    command: ["--config=/etc/otel-collector-config.yaml"]
    volumes:
      - ./collector-config.yaml:/etc/otel-collector-config.yaml
    ports:
      - "4317:4317" # OTLP gRPC receiver
      - "4318:4318" # OTLP HTTP receiver
      - "9464:9464" # Prometheus exporter endpoint (for Prometheus to scrape)
      - "13133:13133" # health_check extension
      - "55679:55679" # zpages extension
    networks:
      - otel-network

  jaeger:
    image: jaegertracing/all-in-one:latest
    container_name: jaeger
    ports:
      - "16686:16686" # Jaeger UI
      - "14250:14250" # Jaeger gRPC collector (for OTel Collector to send to)
      - "14268:14268" # Jaeger HTTP collector
    networks:
      - otel-network

  prometheus:
    image: prom/prometheus:latest
    container_name: prometheus
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml
    command:
      - '--config.file=/etc/prometheus/prometheus.yml'
      - '--storage.tsdb.path=/prometheus'
    ports:
      - "9090:9090" # Prometheus UI
    depends_on:
      - otel-collector # Prometheus scrapes otel-collector
    networks:
      - otel-network

  grafana:
    image: grafana/grafana:latest
    container_name: grafana
    environment:
      - GF_SECURITY_ADMIN_USER=admin
      - GF_SECURITY_ADMIN_PASSWORD=admin
    ports:
      - "3000:3000" # Grafana UI
    depends_on:
      - prometheus
      - jaeger
    networks:
      - otel-network

networks:
  otel-network:
    driver: bridge

collector-config.yaml

# receivers: Define how data gets into the collector
receivers:
  otlp:
    protocols:
      grpc:
      http:
  jaeger: # Optional: if you have older Jaeger clients sending directly to collector
    protocols:
      grpc:
      thrift_http:

# exporters: Define where data goes from the collector
exporters:
  jaeger:
    endpoint: jaeger:14250 # Send traces to Jaeger's gRPC collector
    tls:
      insecure: true # Use insecure connection since it's local
  prometheus: # The collector will expose metrics in Prometheus format at the specified endpoint
    endpoint: "0.0.0.0:9464" # Collector will listen on this port for Prometheus scrapes
  logging:
    loglevel: debug

# service: Define pipelines for processing different data types
service:
  pipelines:
    traces:
      receivers: [otlp, jaeger]
      processors: [] # No specific processors for a basic setup
      exporters: [jaeger, logging]
    metrics:
      receivers: [otlp] # Receive metrics via OTLP
      processors: []
      exporters: [prometheus, logging] # Export metrics via the Prometheus exporter
    logs:
      receivers: [otlp]
      processors: []
      exporters: [logging]

prometheus.yml

global:
  scrape_interval: 15s # By default, scrape targets every 15 seconds.
  evaluation_interval: 15s # Evaluate rules every 15 seconds.

scrape_configs:
  - job_name: 'prometheus'
    static_configs:
      - targets: ['localhost:9090'] # Prometheus scrapes itself

  - job_name: 'otel-collector-metrics'
    static_configs:
      - targets: ['otel-collector:9464'] # Prometheus scrapes the OpenTelemetry Collector's Prometheus exporter endpoint
