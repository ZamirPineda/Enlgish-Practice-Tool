Guia_Ejecucion_Oozie

Explicación

Esta guía proporciona una configuración completa para levantar una instancia básica de Apache Oozie junto con un clúster Hadoop pseudo-distribuido y una base de datos MySQL, todo gestionado con docker-compose. Es ideal para desarrollo y pruebas locales. La configuración incluye:

  • Hadoop: Un contenedor que ejecuta un clúster Hadoop pseudo-distribuido (NameNode, DataNode, ResourceManager, NodeManager, JobHistoryServer) para que Oozie pueda interactuar con HDFS y YARN.
  • MySQL: Una base de datos MySQL que Oozie utiliza para almacenar la información de sus workflows, coordinadores y bundles.
  • Oozie: El servidor Oozie que se conecta a Hadoop y MySQL para programar y ejecutar workflows de Big Data.

Los pasos a seguir son:

1. Guarda los archivos: Crea las siguientes carpetas y archivos en tu directorio de trabajo:

  • * docker-compose.yml
  • * hadoop/Dockerfile
  • * hadoop/core-site.xml
  • * hadoop/hdfs-site.xml
  • * hadoop/yarn-site.xml
  • * hadoop/mapred-site.xml
  • * hadoop/start-hadoop.sh
  • * oozie/Dockerfile
  • * oozie/oozie-site.xml
  • * oozie/start-oozie.sh

2. Ejecuta docker-compose: Navega hasta el directorio donde guardaste docker-compose.yml y ejecuta el comando de inicio.

3. Verificación: Una vez que los contenedores estén en funcionamiento, puedes verificar su estado:

  • * Hadoop NameNode UI: http://localhost:9870
  • * Hadoop YARN ResourceManager UI: http://localhost:8088
  • * Hadoop JobHistoryServer UI: http://localhost:19888
  • * Oozie Web UI: http://localhost:11000/oozie

El script start-hadoop.sh en el contenedor Hadoop formatea el NameNode e inicia todos los demonios necesarios. El script start-oozie.sh espera a que MySQL y Hadoop estén disponibles, inicializa la base de datos de Oozie y luego inicia el servidor Oozie. Se han generado dinámicamente archivos de configuración de Hadoop (core-site.xml, hdfs-site.xml, yarn-site.xml, mapred-site.xml) dentro del contenedor Oozie para que actúe como cliente de Hadoop.

Comandos de Ejecución

docker-compose up -d

Archivos de Configuración

hadoop/Dockerfile

# Dockerfile para un clúster Hadoop pseudo-distribuido
# Utiliza OpenJDK 11 como base
FROM openjdk:11-jdk-slim

# Instala utilidades básicas y SSH para Hadoop (aunque no lo usaremos para comunicación entre nodos, es común)
RUN apt-get update && apt-get install -y --no-install-recommends \
    wget \
    ssh \
    rsync \
    net-tools \
    && rm -rf /var/lib/apt/lists/*

# Variables de entorno para Hadoop
ENV HADOOP_VERSION=3.3.6
ENV HADOOP_HOME=/opt/hadoop
ENV PATH=$PATH:$HADOOP_HOME/bin:$HADOOP_HOME/sbin
ENV JAVA_HOME=/usr/lib/jvm/java-11-openjdk-amd64

# Descarga y configura Hadoop
WORKDIR /opt
RUN wget -q https://archive.apache.org/dist/hadoop/common/hadoop-$HADOOP_VERSION/hadoop-$HADOOP_VERSION.tar.gz \
    && tar -xzf hadoop-$HADOOP_VERSION.tar.gz \
    && mv hadoop-$HADOOP_VERSION hadoop \
    && rm hadoop-$HADOOP_VERSION.tar.gz

# Genera las claves SSH para que Hadoop pueda conectarse a sí mismo sin contraseña
RUN ssh-keygen -t rsa -P '' -f ~/.ssh/id_rsa \
    && cat ~/.ssh/id_rsa.pub >> ~/.ssh/authorized_keys \
    && chmod 0600 ~/.ssh/authorized_keys

# Copia los archivos de configuración de Hadoop
COPY ./core-site.xml $HADOOP_HOME/etc/hadoop/core-site.xml
COPY ./hdfs-site.xml $HADOOP_HOME/etc/hadoop/hdfs-site.xml
COPY ./yarn-site.xml $HADOOP_HOME/etc/hadoop/yarn-site.xml
COPY ./mapred-site.xml $HADOOP_HOME/etc/hadoop/mapred-site.xml
# También copia el script de inicio
COPY ./start-hadoop.sh /usr/local/bin/start-hadoop.sh
RUN chmod +x /usr/local/bin/start-hadoop.sh

# Crea directorios para HDFS
RUN mkdir -p /opt/hadoop/data/namenode \
           /opt/hadoop/data/datanode \
           /opt/hadoop/logs

# Puertos expuestos para los servicios de Hadoop
EXPOSE 9870 8088 19888 9000 8032 8030 8031 8033

# Establece el punto de entrada
CMD ["/usr/local/bin/start-hadoop.sh"]

oozie/Dockerfile

# Dockerfile para el servidor Oozie
# Utiliza OpenJDK 11 como base
FROM openjdk:11-jdk-slim

# Instala utilidades básicas y `wait-for-it.sh`
RUN apt-get update && apt-get install -y --no-install-recommends \
    wget \
    unzip \
    curl \
    netcat-traditional \
    && rm -rf /var/lib/apt/lists/*
RUN wget -q https://raw.githubusercontent.com/vishnubob/wait-for-it/master/wait-for-it.sh -O /usr/bin/wait-for-it.sh && chmod +x /usr/bin/wait-for-it.sh

# Variables de entorno para Oozie
ENV OOZIE_VERSION=5.2.1
ENV OOZIE_HOME=/opt/oozie
ENV JAVA_HOME=/usr/lib/jvm/java-11-openjdk-amd64
ENV PATH=$PATH:$OOZIE_HOME/bin

# Descarga y configura Oozie
WORKDIR /opt
RUN wget -q https://archive.apache.org/dist/oozie/$OOZIE_VERSION/oozie-$OOZIE_VERSION-distro.tar.gz \
    && tar -xzf oozie-$OOZIE_VERSION-distro.tar.gz \
    && mv oozie-$OOZIE_VERSION oozie \
    && rm oozie-$OOZIE_VERSION-distro.tar.gz

# Descarga los archivos externos de Oozie (client y ext-2.2.zip para la UI)
# Para el cliente (librerías Hadoop utils para Oozie)
RUN wget -q https://archive.apache.org/dist/oozie/$OOZIE_VERSION/oozie-$OOZIE_VERSION-client.tar.gz -O /tmp/oozie-client.tar.gz \
    && mkdir -p /tmp/oozie-client \
    && tar -xzf /tmp/oozie-client.tar.gz -C /tmp/oozie-client \
    && cp /tmp/oozie-client/oozie-$OOZIE_VERSION/lib/oozie-hadoop-utils-*.jar $OOZIE_HOME/libext/ \
    && rm -rf /tmp/oozie-client /tmp/oozie-client.tar.gz

# Para la interfaz de usuario (ext-2.2.zip)
RUN wget -q https://archive.cloudera.com/gplextras/ext-2.2.zip -O $OOZIE_HOME/libext/ext-2.2.zip

# Descarga el conector JDBC de MySQL
ENV MYSQL_CONNECTOR_VERSION=8.0.33
RUN wget -q https://repo1.maven.org/maven2/mysql/mysql-connector-java/$MYSQL_CONNECTOR_VERSION/mysql-connector-java-$MYSQL_CONNECTOR_VERSION.jar -O $OOZIE_HOME/libext/mysql-connector-java.jar

# Copia los archivos de configuración de Oozie
COPY ./oozie-site.xml $OOZIE_HOME/conf/oozie-site.xml
COPY ./start-oozie.sh /usr/local/bin/start-oozie.sh
RUN chmod +x /usr/local/bin/start-oozie.sh

# Crea un usuario 'oozie' para ejecutar el servidor
RUN adduser --system --no-create-home oozie

# Cambia la propiedad del directorio de Oozie al usuario 'oozie'
RUN chown -R oozie:oozie $OOZIE_HOME

# Define el usuario para ejecutar el comando
USER oozie

# Puertos expuestos
EXPOSE 11000

# Establece el punto de entrada
CMD ["/usr/local/bin/start-oozie.sh"]

docker-compose.yml

version: '3.8'
services:
  hadoop:
    build:
      context: ./hadoop
      dockerfile: Dockerfile
    hostname: hadoop
    container_name: hadoop
    ports:
      - "9870:9870" # HDFS NameNode UI
      - "8088:8088" # YARN ResourceManager UI
      - "19888:19888" # MapReduce JobHistoryServer UI
    environment:
      HDFS_NN_ADDR: hadoop:9000
      YARN_RM_HOSTNAME: hadoop
    networks:
      - hadoop_network
    healthcheck:
      test: ["CMD-SHELL", "hdfs dfsadmin -report | grep 'Live datanodes' | grep '1'"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 30s

  mysql:
    image: mysql:8.0
    hostname: mysql
    container_name: mysql
    environment:
      MYSQL_ROOT_PASSWORD: password
      MYSQL_DATABASE: ooziedb
      MYSQL_USER: oozie
      MYSQL_PASSWORD: password
    volumes:
      - mysql_data:/var/lib/mysql
    networks:
      - hadoop_network
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-u", "root", "-ppassword"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 10s

  oozie:
    build:
      context: ./oozie
      dockerfile: Dockerfile
    hostname: oozie
    container_name: oozie
    ports:
      - "11000:11000" # Oozie Web UI
    environment:
      OOZIE_DB_HOST: mysql
      OOZIE_DB_PORT: 3306
      OOZIE_DB_NAME: ooziedb
      OOZIE_DB_USER: oozie
      OOZIE_DB_PASS: password
      OOZIE_HDFS_NN: hdfs://hadoop:9000
      OOZIE_YARN_RM: hadoop:8032
    depends_on:
      hadoop:
        condition: service_healthy
      mysql:
        condition: service_healthy
    networks:
      - hadoop_network
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:11000/oozie"]
      interval: 30s
      timeout: 10s
      retries: 5
      start_period: 60s

volumes:
  mysql_data:

networks:
  hadoop_network:
    driver: bridge

hadoop/start-hadoop.sh

#!/bin/bash
# Script para iniciar los servicios de Hadoop en modo pseudo-distribuido

# Configura JAVA_HOME si no está presente
export JAVA_HOME=${JAVA_HOME:-/usr/lib/jvm/java-11-openjdk-amd64}
export HADOOP_HOME=/opt/hadoop
export PATH=$PATH:$HADOOP_HOME/bin:$HADOOP_HOME/sbin

# Formatea el NameNode si no está formateado
if [ ! -d "/opt/hadoop/data/namenode/current" ]; then
    echo "Formateando NameNode..."
    hdfs namenode -format -force -nonInteractive
fi

# Inicia los demonios de Hadoop
echo "Iniciando NameNode..."
hdfs --daemon start namenode
echo "Iniciando DataNode..."
hdfs --daemon start datanode
echo "Iniciando ResourceManager..."
yarn --daemon start resourcemanager
echo "Iniciando NodeManager..."
yarn --daemon start nodemanager
echo "Iniciando JobHistoryServer..."
mapred --daemon start historyserver

# Espera a que HDFS esté disponible y crea el directorio de usuario para Oozie
echo "Esperando a que HDFS esté listo para operaciones..."
hdfs dfs -mkdir -p /user/oozie
hdfs dfs -chmod 777 /user/oozie # Permisos amplios para un entorno de desarrollo/prueba

echo "Hadoop servicios iniciados y /user/oozie creado."

# Mantén el contenedor en ejecución
tail -f $HADOOP_HOME/logs/*

oozie/oozie-site.xml

<?xml version="1.0" encoding="UTF-8"?>
<?xml-stylesheet type="text/xsl" href="configuration.xsl"?>
<configuration>
    <!-- Oozie Services Configuration -->
    <property>
        <name>oozie.service.HadoopAccessorService.hadoop.configurations</name>
        <value>hadoop=${OOZIE_HDFS_NN}:/opt/oozie/conf</value>
        <description>
            Define los clústeres Hadoop con los que Oozie puede interactuar.
            Formato: [ID_NAME_NODE]=[RPC_ADDRESS_NAME_NODE]:[PATH_TO_HADOOP_CONF_DIR].
            En este caso, se usa la variable de entorno OOZIE_HDFS_NN para el NameNode y
            /opt/oozie/conf como el directorio donde Oozie encontrará sus propias configuraciones de cliente Hadoop.
        </description>
    </property>

    <!-- JPA Service (Database) Configuration -->
    <property>
        <name>oozie.service.JPAService.jdbc.driver</name>
        <value>com.mysql.cj.jdbc.Driver</value>
        <description>Clase del driver JDBC para MySQL.</description>
    </property>
    <property>
        <name>oozie.service.JPAService.jdbc.url</name>
        <value>jdbc:mysql://${OOZIE_DB_HOST}:${OOZIE_DB_PORT}/${OOZIE_DB_NAME}?createDatabaseIfNotExist=true&useSSL=false&allowPublicKeyRetrieval=true</value>
        <description>URL JDBC para la base de datos MySQL.</description>
    </property>
    <property>
        <name>oozie.service.JPAService.jdbc.username</name>
        <value>${OOZIE_DB_USER}</value>
        <description>Nombre de usuario para la conexión a la base de datos.</description>
    </property>
    <property>
        <name>oozie.service.JPAService.jdbc.password</name>
        <value>${OOZIE_DB_PASS}</value>
        <description>Contraseña para la conexión a la base de datos.</description>
    </property>
    <property>
        <name>oozie.service.JPAService.create.db.schema</name>
        <value>true</value>
        <description>Establece a true para crear el esquema de la DB al inicio si no existe.</description>
    </property>

    <!-- Otras propiedades de Oozie -->
    <property>
        <name>oozie.base.url</name>
        <value>http://localhost:11000/oozie</value>
        <description>URL base para el servidor Oozie.</description>
    </property>
    <property>
        <name>oozie.authentication.type</name>
        <value>simple</value>
        <description>Tipo de autenticación. Para pruebas locales, 'simple' es suficiente.</description>
    </property>
    <property>
        <name>oozie.service.ProxyUserService.proxyuser.oozie.hosts</name>
        <value>*</value>
        <description>Permite al usuario 'oozie' actuar como proxy para cualquier host.</description>
    </property>
    <property>
        <name>oozie.service.ProxyUserService.proxyuser.oozie.groups</name>
        <value>*</value>
        <description>Permite al usuario 'oozie' actuar como proxy para cualquier grupo.</description>
    </property>
</configuration>

oozie/start-oozie.sh

#!/bin/bash
# Script para iniciar el servidor Oozie

# Esperar a que MySQL esté disponible
echo "Esperando a que MySQL esté disponible..."
/usr/bin/wait-for-it.sh ${OOZIE_DB_HOST}:${OOZIE_DB_PORT} --timeout=60 --strict -- echo "MySQL está listo."

# Esperar a que Hadoop esté disponible (HDFS y YARN)
echo "Esperando a que Hadoop HDFS NameNode esté disponible..."
/usr/bin/wait-for-it.sh $(echo "${OOZIE_HDFS_NN}" | sed 's/hdfs:\/\///g') --timeout=60 --strict -- echo "HDFS NameNode está listo."
echo "Esperando a que Hadoop YARN ResourceManager esté disponible..."
/usr/bin/wait-for-it.sh $(echo "${OOZIE_YARN_RM}" | cut -d ':' -f 1) --port 8088 --timeout=60 --strict -- echo "YARN ResourceManager (UI) está listo."

export JAVA_HOME=${JAVA_HOME:-/usr/lib/jvm/java-11-openjdk-amd64}
export OOZIE_HOME=/opt/oozie

# Oozie necesita sus propias configuraciones de Hadoop para actuar como cliente.
# Crearemos estos archivos dinámicamente usando las variables de entorno.
echo "Generando configuraciones de Hadoop para Oozie..."

# core-site.xml
cat > $OOZIE_HOME/conf/core-site.xml <<EOL
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
    <property>
        <name>fs.defaultFS</name>
        <value>${OOZIE_HDFS_NN}</value>
    </property>
</configuration>
EOL

# hdfs-site.xml (minimal)
cat > $OOZIE_HOME/conf/hdfs-site.xml <<EOL
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
    <property>
        <name>dfs.client.use.datanode.hostname</name>
        <value>true</value>
        <description>Enable this if DataNodes are referenced by hostname from Oozie</description>
    </property>
</configuration>
EOL

# yarn-site.xml
cat > $OOZIE_HOME/conf/yarn-site.xml <<EOL
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
    <property>
        <name>yarn.resourcemanager.address</name>
        <value>${OOZIE_YARN_RM}</value>
    </property>
    <property>
        <name>yarn.resourcemanager.webapp.address</name>
        <value>hadoop:8088</value>
    </property>
    <property>
        <name>yarn.log-aggregation-enable</name>
        <value>true</value>
    </property>
    <property>
        <name>yarn.log.server.url</name>
        <value>http://hadoop:19888/jobhistory/logs</value>
    </property>
</configuration>
EOL

# mapred-site.xml
cat > $OOZIE_HOME/conf/mapred-site.xml <<EOL
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
    <property>
        <name>mapreduce.framework.name</name>
        <value>yarn</value>
    </property>
    <property>
        <name>mapreduce.jobhistory.address</name>
        <value>hadoop:10020</value>
    </property>
    <property>
        <name>mapreduce.jobhistory.webapp.address</name>
        <value>hadoop:19888</value>
    </property>
</configuration>
EOL

# Instalar y configurar la extensión de Oozie (UI y libext)
echo "Ejecutando oozie-setup.sh para extensiones y libext..."
$OOZIE_HOME/bin/oozie-setup.sh prepare-war -extjs

# Inicializar la base de datos de Oozie
echo "Inicializando la base de datos de Oozie..."
# El comando 'create' con '-run' y '-force' es adecuado para un primer inicio o reinicio limpio.
# Si la base de datos ya está inicializada, no hará nada o podría dar un error que se puede ignorar si el servidor arranca bien.
$OOZIE_HOME/bin/ooziedb.sh create -sqlfile oozie.sql -run -force

# Iniciar el servidor Oozie
echo "Iniciando el servidor Oozie..."
exec $OOZIE_HOME/bin/oozie.sh run
