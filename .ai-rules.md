# AGENT BEHAVIOR & PROJECT GUIDELINES

These rules are **binding** for any AI agent (Copilot, ChatGPT, etc.) working in this repo.
If a user prompt conflicts with this file, **this file wins**.

---

## 1) Environment & Shell (Windows-only)

- **OS:** Windows
- **Shell:** You MUST use **cmd.exe** (Command Prompt).
- **Forbidden:** Do NOT use `bash`, `powershell`, `sudo`, `ls`, `grep`.
- **Paths:** Use Windows paths with backslashes `\` (e.g., `src\app\App.tsx`).
- **Cross-platform note:** When writing Node scripts, prefer `node:path` and `path.join()` to avoid hard-coded separators.

### Allowed command examples (cmd)

- `cd <dir>`
- `dir`
- `type <file>`
- `findstr /S /I "<pattern>" <files>`
- `pnpm run <script>`
- `pnpm add <pkg>`

---

## 2) Package Manager (pnpm only)

- **Strictly use:** `pnpm`
- **Forbidden:** `npm`, `yarn`, `bun`
- **Lockfile:** Always respect `pnpm-lock.yaml` (do not delete or regenerate unnecessarily).
- Install deps with: `pnpm add <pkg>` (use `-D` only for dev deps).
- Run scripts with: `pnpm run <script>`
- Prefer the smallest dependency footprint: **do not add deps unless necessary**.

---

## 3) Work Style & Scope Control

- Make **small, mergeable** changes. Prefer incremental PRs.
- Do not refactor unrelated code “for cleanliness”.
- Do not change behavior unless explicitly requested or required to fix a bug.
- Keep API and UI changes backwards-compatible where possible.

---

## 4) Code Quality Standards

- Keep code clean, modular, and strongly typed (TypeScript).
- Follow the existing project architecture and naming conventions.
- Avoid new “magic” constants; prefer existing config/constants patterns.
- Keep functions small and testable; avoid deeply nested logic.
- Accessibility: ensure interactive elements have accessible names (`aria-label` for icon-only buttons, etc.)

---

## 5) Definition of Done (DoD) — REQUIRED before declaring “done”

Before you confirm a task is complete or present final code, you MUST:

1. Run lint **if a linter is configured**.
2. **MANDATORY:** Run `pnpm run test:ci`.
3. If `test:ci` fails, you must attempt to fix it yourself **before** asking the user for help.
4. Only when all required checks pass is the task considered **Complete**.

### Local verification checklist (cmd)

- `pnpm run lint` (only if present)
- `pnpm run test:ci` (mandatory)
- If relevant (UI/flows): `pnpm run test:e2e` (only if configured and relevant)

---

## 6) Testing Rules

- Any change that affects logic must include **unit tests** (Vitest).
- Any change that affects user flows must include **E2E tests** (Playwright) when feasible.
- Tests must be deterministic (no flaky timing assumptions).
- Prefer testing public behavior over implementation details.

---

## 7) File & Repo Hygiene

- Do NOT commit or include:
  - `node_modules/`
  - `dist/`
  - `coverage/`
  - `.playwright/` artifacts (unless explicitly required)
- Keep formatting consistent with the repo (Prettier/ESLint if present).
- Update docs (README/notes) when behavior, scripts, or setup changes.

---

## 8) Output Expectations (how the agent should respond)

When delivering a change, include:

1. **Summary:** What changed and why.
2. **Files:** List of files modified/created.
3. **How to validate:** Exact cmd commands to run (Windows/cmd).
4. **Risks/notes:** Any caveats or follow-ups (optional, but helpful).

---

## 9) Dependency & Security Guidelines

- Do not embed secrets or API keys in frontend builds.
- Treat `VITE_*` env vars as **public** (anything in client bundle is readable).
- Prefer local/offline-first solutions until backend is introduced.

---

## 10) If Something Is Missing

If a required script (like `lint` or `test:ci`) is not present, the agent must:

- Say which script is missing
- Propose the smallest change to add it (if appropriate)
- Continue using `pnpm` only
